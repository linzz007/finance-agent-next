网页和行情工具故障，模型服务保持在线。Q29 要求隔离主机，因此没有在当前
主机直接运行。

`data/finance_eval_v1/` 中的 JSON 保存完整 ID、会话 ID、答案、动作摘要和耗时。

## 优点

1. 金融普通对话入口确实加载了金融 Prompt、Skills 和工具包。除 Q01 外，
   有效运行都先创建 `research.plan` 再取材。作者/日期定位与逐篇读文可用；
   Q05/Q06、Q10-Q13 是正面样本。
2. 较好的答案保留了作者、日期、原文行号，并区分作者预测与已证实事实。
   Q30 也证明外部核验失败时，系统可以诚实、可追溯地降级。
3. Trace 暴露了模型动作、门控、证据审计、来源读取、委派和停止原因，
   能将不同失败机制分开定位，而不是只留下笼统报错。

## 缺点与归因

1. **P0，交付可靠性：**取到证据不等于能交付答案。Q03/Q04/Q15/Q19/Q21/Q25
   以 `gate_blocked` 结束；Q07/Q09/Q20/Q24 为 `repeated_tool_failure`；
   Q08/Q16 耗尽模型调用。多条降级回答称计划没有待办，但用户问题尚未回答。
   计划完成当前更多衡量的是取材步骤，不是交付结果。Q03 的审计还拿较早的
   持仓日期怀疑较晚的真实行情日期，属于具体的审计上下文误用。
2. **P0，研究范围控制：**Q07 读了 39 篇，Q14 耗时 503 秒。Q08/Q16
   反复恢复被换出的上下文，没进入有效合成。需要可靠的取材收束、紧凑证据
   状态和最终发布/明确阻塞机制；这不是要求固定分析模板。
3. **P1，跨来源关系：**Q14 证明“每句话都能找到引用”和
   `answer_claim_audit=accept` 仍不足以证明两位作者构成共识。skeptic 将
   其中一项标为推导而非明确表达，最终答案仍写成共识。此处人工关系审查
   结论高于模型审计的 `accept`。
4. **P1，复核与权限契约：**Q17/Q22 触发广泛比较的独立复核要求，却在
   `tool_denied` 停止；Q18 的模型动作类型不合法。复核路径可观测，但端到端
   执行不稳定。A1 深读已有成功样本；B3 合成、D* 修订、E* 委派复核以及
   C1 上下文恢复仍不能据这套结果宣布整体通过。
5. **环境与验收边界：**本机 7890 HTTP 代理间歇拒绝/关闭模型连接。
   Q21/Q25/Q26-Q28 已重跑，以区分环境错误与产品行为。Q29 未验证。
   实时行情随时间变化，应以运行 ID 与来源观察作审计记录，不把数值当永久
   基线。本轮人工抽查了原文行，不等于对全部被引市场事实逐条独立核验。

## 修复优先级

1. 修复最终答案门控与审计器的交接；`done` 目标应对应已交付答案，做不到则
   明确 `blocked`。先用 Q03、Q04、Q21 回归。
2. 为 `context.open` 和研究产物工具失败建立有界重试与紧凑证据账本；
   用 Q08、Q16、Q24 回归。
3. 跨文章关系本身必须有明确支持，skeptic 的异议应影响最终表述；
   用 Q14 回归。
4. 对齐复核委派与工具权限契约，再重跑 Q17、Q18、Q22。
5. 在隔离主机跑 Q29，并为下一版基线冻结文章/行情快照。
