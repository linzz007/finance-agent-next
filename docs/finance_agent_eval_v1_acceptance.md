## 1. 验收记录与判定

每条 Query 单独运行，保存 `query_id`、原始问题、文章目录快照/文件哈希、Wiki 与持仓版本标识、运行时钟、模型及工具配置、`session_id`、`run_id`、完整 AgentStep Trace、工具返回、最终答案和人工结论。所有“最近一个月/近几个月/近期/最近五篇”等相对范围都以本轮 `research_clock` 固定并保存解析后的筛选边界；作者的“最近五篇”还需保存实际排序和入选 ID。Q03/Q21 的动态行情另存数据获取时刻、市场日历/时区、供应方与原始快照；Q30 在隔离环境注入外部访问失败。不要把实际持仓明文复制进公开验收记录。

人工分别判定 **内容**、**证据**、**链路** 三栏：`通过`、`不通过`、`无法判定`。只有三栏均通过才算该 Query 通过。`无法判定` 仅用于快照、Trace 或测试环境缺失，不能用来掩盖 Agent 的失败。记录失败归因：数据缺失、工具/权限、规划/选材、阅读、比较/推理、事实核验、最终表达、Trace 缺口或测试设计。资料确实缺失时，诚实说明边界可以通过相应边界题；普通研究题仅返回通用降级文字、标题清单或行情清单不能算完成。

终稿审核、实际交付与业务验收分别记录。规范字段使用 `delivery_status`、`delivery_mode`、`verification_status`、`evidence_coverage`、`answer_audit_coverage`、`trace_contract` 和 `semantic_review`，语义见接口契约。旧 Trace 中的 `audit_accepted`、`disputed_partial` 等可以作为历史观测保留，不能当作新的规范枚举。`delivery_status=done` 只说明安全结果已送达，`delivery_mode=source_only` 表示交付材料形态，不证明研究完成。

争议不是自动通过或自动失败：人工须核对是否回答问题、未核实结论是否限制措辞、作者原观点是否有原文依据、反驳是否有独立证据或明确标为审核意见、重要条件是否保留。审核模型失败或覆盖不完整不能自动要求丢弃安全的完整分析；安全问题只限制受影响内容。核心任务缺失或只剩来源清单时，普通研究题内容栏仍不通过；这与“已安全交付、但研究不完整”可以同时成立，不能为了让测试通过而降低答案质量要求。

争议移出后仍检查最终文档是否可读：不得删除 Markdown 表格的分隔行、留下空的核心结论或把多个核心比较维度仅替换成“见争议项”。`source_only` 的摘录须是与问题相关的正文；标题、发布日期、图片占位、重复的固定开头或随意第一行不能充当已提炼的作者观点。若审核异议明显指向非主张的排版行，要在人工验收中记录审核误判，不能以 `disputed_partial` 掩盖输出结构损坏。

引用和数值的硬失败：编造文章、作者、日期、行情或 `EvidenceRef`；把 `article.list` 的标题当已读正文；把作者共识说成市场事实；把未到期预测说成已证实；把主 Agent 的 `research.verify` 说成独立 Subagent 复核；读了授权目录外文件；把未完成的目标标成完成。同一数值主张的期初/期末值、基准日期和涨跌幅必须同口径且可复算；不同基准算出的百分比必须另行标注，不能混写。人工应打开被引文章的对应正文行/公开来源/行情快照核对，不把模型审计的 `accept` 当语义真值；确定性数值门控未覆盖的表述也要抽查。

模型传输的增量检查见[变更 007](changes/007-responses-transport-and-delivery.md#5-分层验收与停止)
和[接口 6.4-6.5](finance_agent_interface_contracts.md#64-optional-responses-text-transport)。
JSON/SSE 终态、断流不执行、截断不恢复成完整稿及单次请求账本先独立检查；

## 2. Trace 检查点

Trace 检查沿 `run_id` 和工具/证据 ID 建立关系，而不只按展示顺序逐行搜索：Runtime 的部分 `tool_result` 在 AgentLoop 结束后补写，须结合 `turn_index`、主 Agent `model_call` 的动作、`gateway.calls` 和证据账本重建实际调用顺序。

| 编号 | 关键节点与必须检查的事实 | 适用范围 |
| --- | --- | --- |
| T0 路由与插件 | 同一 `session_id/run_id` 进入金融 `general_chat`/`chat_agent_loop`；`plugin_load` 的 Prompt、skill、toolkit 哈希/列表可见。没有误入 `/report` 固定工作流。 | 全部 |
| T1 目标保持 | 首次取材前主 Agent 调用 `research.plan(create)`；目标和 `scope` 覆盖用户的作者、时间、资产、交付问题及证据需求。结束前研究目标逐项 `done` 或带理由 `blocked`；`evidence_audit.research_plan.research_pending_count=0`。另查终态 `research_delivery.research_plan.delivery_status`：成功送达答案才是 `done`，执行中断/未送达须为 `blocked`；`done` 不代表内容完整或可信。计划不得把具体读法和是否委派写死。 | 全部，包括简单查值与失败题 |
| T2 来源发现 | `article.list` 的作者/日期参数与问题相符；查看 `evidence_audit.article_list_history`。`article.list` 仅证明文章存在，作者观点必须有该文章的 `article.read` 正文行或成功子任务的正文证据。 | 本地文章题 |
| T3 单篇阅读 A1 | 从 `article_id -> 实际正文范围/EvidenceRef -> 文章理解中的重要说法` 可追溯。明确深读且全文可访问时须覆盖全文及重要限定，形成文章级理解；未完成不能称完成。已选深读能力全文适配时应将全文纳入分析输入，确实超预算才分段整合；分次取得正文不要求分次分析。旧 `article.study(deep)` 仍须核对分段输入、归并与失败，但不能据此宣称符合全文优先新设计。无相关内容允许如实返回；skim 不冒充深读。主 Agent 直接读完并整合同样可通过，不强制卡片、插件或第二次归并调用。详见第 6 节。 | 读文章题 |
| T4 跨文合成 B3 | 比较所用每篇文章有独立日期、作者、理解和正文依据；共识、分歧、变化或互补须连回不同文章的重要说法及限定，不强制都转为 claim ID。主 Agent 可自行或委派综合，检查实际执行者可见的理解、条件、局限和必要展开；不要求父 Agent 重做全部分析。读取、任务分析、综合考虑范围分别核对，子任务全部返回不自动等于全量综合。若用了 v1 `research.synthesize`，核对 `card_ids`、`claim_ids`、`relation_audit` 与被拒关系；这不证明新交接已实现。`no_supported_relation` 不得被改写为共识。 | 多篇比较/时间变化题 |
| T5 外部事实 | `web.search/source.discover` 只是线索；关键网页事实须有 `web.open/source.fetch` 正文证据。行情须能回溯 `market.catalog -> market.snapshot -> market.metrics/series` 或实际公开网页来源，并核对品种、单位、时间范围、已完成交易日与供应方；不把日线快照写成实时价。 | 行情与外部核验题 |
| T6 验证与答案审核 D* | 实质分析后须记录 `research.checkpoint` 及验证决定、结果和缺口，不强制特定核验工具或外部来源；新证据后更新。重要审核目标由主 Agent 选择，核对目标类型、引用、条件、外部核查意图和实际核验结果，不按每句话强制审核。若发生 `answer_claim_audit`、`cross_review` 或结构修复，核对真实目标、覆盖、修订、实际重试与 `answer_review_resolution`；核验不足/审核失败应保留安全分析并披露，不能仅因覆盖不完整退化为材料清单。规范争议状态为 `verification_status=disputed`，旧值只作历史读取。人工仍须检查归因、条件、反证和未选中但影响核心结论的遗漏目标。 | 实质分析题；纯计数和元数据不强制金融语义深审 |
| T7 受控委派 | 主 Agent 自主决定是否使用 Subagent，阅读、跨篇分析、综合、复核及候选稿可按需委派，不因作者数量或文章数量自动要求某角色。若启动，核对 `subagent_plan`、`subagent_context`、`subagent_delegate`、子任务实际输入/读取、对应结果契约及 `subagent_evidence_audit`；阅读和综合保留连贯正文与证据外层，而非强制 claims。父 Agent 使用前须有合法证据合并及结果处置；不要求重写子稿或亲自重复其全部分析。合法部分结果不得被标成成功子任务证明。若声称独立外部核查，必须有实际独立来源；阅读结果、主 Agent `research.verify` 或另一模型意见不能代替。 | 实际委派或宣称独立复核时 |
| T8 上下文 C1/E* | 区分原文观测、完整文章理解、当前综合工作视图与实际执行者的可见输入；保存成功不表示已进入模型。完整理解适配时不强制额外摘要；真实压力下换出需保留 ID/版本/校验和及恢复链。需要旧精确内容时通过授权恢复或重读，不把换出标记当证据，也不强迫使用有来源理解的每次综合都恢复全部原文。子任务展开仅限获授材料。无压力时换出检查标记“不适用”，不为验收强行压缩。 | 条件触发 |
| T9 结束状态 | 答案回答计划目标或明确未完成项、缺口及范围。核对 stop reason、`research_delivery` 和独立状态字段。安全结果实际送达可为 `done`，包括 `full/qualified/source_only`；没有安全研究内容可交付才为 `blocked`。预算耗尽、模型或工具失败不能按错误类型一律判 blocked，应核对实际交付；同样不能把带限制交付写成研究完整或已验证。 | 全部 |

每条 Query 同时检查“**该走的节点走了**”与“**不该声称的能力没有声称**”。`article.study`、`research.synthesize`、`research.verify`、Subagent、`context_offload` 是可选路径；单次缺席不构成失败。为了证明 A1/B3/D*/E* 插件确实可用，还需在整套验收结果中选至少一次真实触发样本核查各可选路径；若 30 次都未触发某路径，记为“该能力未验收”，不要把它误报为通过。

`plugins/tools/finance_research.json` 对 `research.plan` 的描述已与金融 System Prompt 和 Runtime 对齐：每轮首次取材前创建计划（T1），具体取材与分析方法仍由主 Agent 选择。

变更 010 的增量检查：T0 区分目录可用模块与 `initial_loaded_skill_modules`（金融初始为空）；首次输入只包含主 Prompt、短能力目录、工具用途和三个基础参数 Schema。`skill_load`/`tool_describe` 及实际模型输入应能回查按需披露的正文/参数与校验和。`skill.open`、`tool.describe(name)` 是受控说明查询，可以先于计划，但不能将此例外扩展到文章、网页、行情或委派取材；T1 仍要求业务取材前规划。非法 ID/路径、不可见工具或加载失败不可静默放宽权限。30 条 Query 及内容/证据要求不变，不把按需加载本身当作金融质量通过。

## 3. 各场景通用内容标准

- 简单查值：给出可重算的数值、统计口径/截至时间和来源；不为简单题强制深读或委派。
- 单篇深读：覆盖论点、支撑、重要条件、反例/空白，解释文章自身的推理，而不是只改写摘要；文章中的市场数字不因被引用而变成已核实事实。
- 作者画像：使用多篇且尽量跨时间的正文，区分稳定方法和偶发话题，承认抽样范围。
- 时间变化：按实际发布日期排列，区分事前预期、事后解释、延续、修正与未涉及；文件名、标题、正文日期冲突要核实。
- 多作者比较：每位作者至少有相关正文证据；比较同一个问题和时间范围，允许“无直接观点”，不为凑共识而强行配对。
- 外部核验：把待核查主张拆为事实、观点、预测、因果和推断；行情/官方记录只支持其实际包含的部分，独立来源和检索线索不可混淆。
- Wiki/持仓：使用当前文件权威值与 Wiki 偏好作为个人背景，不把个人资料当行情事实；禁止推测持仓成本、收益、风险偏好和交易建议。
- 边界题：明确已尝试和被拒绝的范围；零结果、冲突或联网失败不能诱发伪证据、越权读取或假装核实。

## 6. 文章理解交接与全文优先的增量检查

依据用户于 2026-10-16 确认的[架构第 4、5、8 节](architecture.md#4-单篇文章与文章集合)、[交接契约](finance_agent_interface_contracts.md#31-target-single-article-handoff)及[可选阅读 Subagent](finance_agent_interface_contracts.md#32-controlled-reading-subagent)。本节将已确认行为转为检查要点，不添加第 31 条 Query，不新增固定章节、逐句审核、固定委派或自动评分要求。具体字段、事件及兼容映射已在[正式契约第 8 节](finance_agent_interface_contracts.md#8-versioned-research-integration-contract)实现为严格 Schema；离线接口/链路与真实文章理解质量分别验收。

| 检查点 | 应观察的证据 | 不能据此声称 |
| --- | --- | --- |
| 任务保持 | 单篇分析收到原问题、具体任务、文章与范围；关注点按需传递，而非复制全部父对话或将不同问题套成同一张表 | 任务参数合法即表示内容有价值 |
| 全文适配 | 深读选择全文或分段的理由、配置与预算估算可追溯；适配时全文纳入成功的分析调用；分段时有真实超预算依据和文章级整合 | 读工具返回全文即表示分析模型收到全文，或模型收到即表示完全理解 |
| 交接内容 | 主要结果能围绕任务解释文章主线或所问结论，保留重要条件、作者归因、模型解释和局限；细粒度主张可选 | claims 数量或正文长度证明深入阅读 |
| 原文联系 | 重要说法能沿理解中的证据联系回到本次实际观测的文章版本与相关正文；精确引句核对原文 | 引用合法就证明推断成立，或全部句子必须成为 claim |
| 综合利用 | 主 Agent 或综合能力实际看到相关连贯理解及其日期、条件与局限；不要求先生成卡片。发现具体缺口可补读，有回读才记录回读 | 新增一个文本字段就已使用了理解，或所有文章必须重新读一遍 |
| 故障与范围 | 部分取得、分析输入不全、归并失败、无相关内容和模型失败分别记录；保留有效结果但不虚报完成；源版本变更可识别 | 有候选正文就把所有步骤标成成功，或失败就删除所有分析 |
| 上下文恢复 | 实际触发换出时，完整理解及原始证据仍有恢复链；工作视图标明其来源和范围 | 保存成功即意味着仍在活跃上下文中，或摘要是独立事实来源 |
| 阅读子任务自主性 | 实际委派时，任务、授权文章与工具可追溯；子任务可以直接返回或为具体缺口回读，不强制第二轮；主 Agent 自读路径仍可使用 | 每篇必须派任务，或工具调用越多越深入 |
| 子任务权限与结果接收 | 拒绝超出本轮/任务授权的文章、文件和工具；父任务只接收通过身份、版本和证据检查的结果，来源合法的部分理解保留失败状态 | 子 Agent 自称已读即视为合法，或子任务失败等于所有已观察证据必须丢弃 |

离线验证使用临时文章覆盖全文适配、超预算分段、缺失范围、源变更和失败恢复；真实业务验证沿用同一快照下的 Q04-Q06、Q08、Q11-Q12 及 Q14 等相应题目。具体执行组合、重复次数与预算在实施迭代中确定；不能只用临时数据的结构通过替代真实文章的理解质量。用户认可的回答样例用来讨论解释价值，不作为其中观点已经正确的标准答案。

阅读子任务的离线验证另覆盖：一次完成、为明确缺口回读、文章越界和未授权工具被拒、结构修复不新增事实、传输失败不混接片段、超时后合法部分结果接收，以及伪造/过期 EvidenceRef 不进入父证据账本。真实验收须至少保留一次实际阅读子任务 Trace；无缺口时不为验收强迫回读，可在隔离测试中验证回读能力。固定串行分段模型调用不能单独证明已经实现阅读 Subagent 的自主工具循环。

## 7. 多篇综合与委派分析的增量检查

依据[架构第 5、8 节](architecture.md#5-跨文章分析)、[综合交接](finance_agent_interface_contracts.md#41-target-multi-article-synthesis-and-context-handoff)及[确认记录第 9 节](changes/003-article-understanding-review.md#9-已确认的多篇综合上下文与分析委派)。本节只把已确认职责变成检查点，不新增 Query、固定角色、数值通过线或必经工具；新版综合已有隔离模型夹具的 Runtime 链路验证，真实金融质量尚未验收。

| 检查点 | 应观察的证据 | 不能据此声称 |
| --- | --- | --- |
| 总体目标与执行分工 | 主 Agent 保持原问题、计划、任务边界、结果取舍及发布；自行或委派完成的阅读、分析、综合与复核均可追溯 | 只有主 Agent 亲自分析才符合设计，或全部委派就自动完成目标 |
| 综合输入真实可见 | 实际执行者收到相关完整理解或明确标注范围的工作视图、作者日期、来源版本、条件和局限；旧卡片接口与新路径分别检查 | 只传 ID 就证明模型读到了内容，或强制生成 cards/claims 才算合成 |
| 三种覆盖不混用 | 实际读取范围、任务分析输入/有效结果、综合考虑及排除/未处理范围分别可核对；排除判断由 Agent 给出，有需要时人工检查 | Runtime 认证语义无遗漏，或每个子任务成功就等于全部文章已被综合 |
| 少数观点与时间条件 | 人工打开相关原文，对照综合是否保留能改变结论的反向观点、期限、条件及事前/事后差异；无可比关系可如实说明 | 多篇一致就是独立事实验证，或不同主题必须比较出关系 |
| 上下文适配与保真 | 无真实压力时完整理解可直接使用；有压力时工作视图围绕任务保留条件、反例、缺口和上游引用，完整理解及原文仍能按权限恢复 | 工作视图更短就更好，或父 Agent 必须重复装入所有子任务原文 |
| 有目的展开与权限 | 条件不清时可在授权内展开理解或回读；超范围需要返回具体缺口，父 Agent 决定是否追加。拒绝借材料 ID 浏览整个父存储、跨运行或越界文件 | 每次必须展开/联网/再派一轮，或拿到父材料句柄就获得父权限 |
| 结果接收及证据链 | 综合重要说法经实际理解/视图或直接证据回到原文；Runtime 合并合法子证据，父 Agent 对采用、修订、排除或补充有可见处置 | 子任务文字是独立来源，或已读/已考虑文章必须全部成为最终引用 |
| 失败与版本变化 | 缺失范围、子任务失败、视图过期、无相关内容与争议均可区分；合法部分分析保留，源变更不静默混用；最终披露局限 | 有部分稿就记全量完成，或综合子任务失败必然使全部安全分析消失 |

离线验证使用临时文章和隔离运行，覆盖：完整理解能直接进入综合；压力下工作视图换出与精确恢复；授权材料展开与未授权父产物/跨运行拒绝；成功子任务结果集合中仍有未纳入综合的材料；低频反例、时间条件和不同主题不可比；过期视图失效；部分失败不升级状态也不丢失合法结果。确定性校验只能证明接口与来源边界；反例是否被理解、解释是否有价值仍需真实人工验收。

真实验收沿用第 6 节的文章理解样本及 Q08、Q11-Q12、Q14-Q18 等适用题目，区分主 Agent 自行综合和实际委派综合。整套能力验收需有可打开的委派综合样本；某次未选择委派不是该题失败，整套无触发则记该能力未验证。主 Agent 不重复全量分析且能依据子结果完成目标应允许通过；流程合法但答案遗漏关键观点、抹平条件或脱离问题仍须记录内容问题。明确全部覆盖的语义先用隔离范围案例检查，不偷偷改写 1.0 Query。具体重复次数与运行预算在实现迭代中确定。

## 8. 版本化接口与运行内存储的增量检查

依据[正式接口契约第 8 节](finance_agent_interface_contracts.md#8-versioned-research-integration-contract)及[确认记录第 10 节](changes/003-article-understanding-review.md#10-已确认的接口与存储映射)。本节是检查清单，不能把每一行自动记为已通过；已执行结果和未覆盖项集中在变更 004。沿用原 30 条 Query；离线接口用隔离夹具补充，不增加金融业务路径、强制 Subagent、自动评分或逐句审核要求。

| 检查点 | 应验证的事实与失败分支 | 对应记录 |
| --- | --- | --- |

## 9. 审核收敛与候选交付回放

用户确认变更 008 方案 A；按接口第 5.2 节验证，不降低原 30 条 Query 的内容要求。离线夹具不调用真实模型、不读取私有原文。

- 目标完成且 retain 时，非空 limitations 不触发全文重写；证据不足可完成审核但不能标 verified。
- 真实缺少参与文章、未传完整已读片段、结构/传输失败时保持实际 partial/failed；完成目标可复用，未完成目标不能伪装成功。
- 完整候选在审核前保存；审核/修订超时、断流、工具或格式失败后保留已有合法正文及真实错误，不只返回材料清单。
- 新稿无效、存储失败、无完整候选、来源变化分别回放；旧版回退不得清除仍适用的问题，伪证据不得用免责声明放行。
- 同一目标换到远处无关段落后，不得清除原有语义异议；实际覆盖争议段落的完成重审可以关闭该异议。补齐缺失参与文章/恢复审核调用后，成功重审须关闭对应旧缺口；不得因为诊断是平铺字段或追加了真实证据而永久保留。部分批次只关闭实际完成目标的问题。独立复核来源检查也须覆盖中断候选选择，不能重新发布已拒绝的虚假复核声明；尚未复核或缺状态说明不算伪造来源，应保留安全正文并补真实未完成说明，分别回放 gate_blocked 和 model_error。
- 主 Agent 可以继续或明确带局限交付，无固定三轮改写；相同输入不重复成功审核，新材料、上下文或限定变化使对应缓存失效。
- 正文与表格保留，争议、作者观点与反向理由并列；done、qualified、覆盖与核验状态分开。只有最终提交成功才写 delivery done。
- 结构化完成器首轮和恢复请求均实际包含完整嵌套输出 Schema（含字段、类型、枚举和定义引用），明确 final/output 外层与内部数据的区别；不靠猜测别名、放宽来源校验或新增重试掩盖契约缺失。确认原始调用消息与来源内容未被修改，既有共享请求上限仍生效。
- full、qualified、source_only 的已交付与未交付终态均不遗留 pending 研究目标；未记录完成的目标标 blocked，保留此前进度及停止原因，不能自动记 done。重载持久化计划后结果一致，交付状态仍独立。
- Runtime 标记的 `review_execution_gap` 显示为审核未完成的目标及原因，不当作反驳；纯语义争议、混合问题、未知/历史异议以及候选版本回退分别回放。后续审核失败或空目标不清除已有实质问题，也不把执行缺口升级为事实已验证。模型不能自行添加该内部标签豁免金融异议。

离线结果与有限次数的真实业务复验分别记录在变更 008。离线通过不等于 Q04/Q14 内容通过，不宣称商业化并发或 SLA。
