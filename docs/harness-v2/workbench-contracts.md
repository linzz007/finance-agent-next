[100](../changes/100-h2-workbench-entry.md) and
[109](../changes/109-h2-test-record-browser.md) and

## HTTP

Prefix: `/api/h2-workbench`. Single local user, bound to loopback by the launcher.
This is not a multi-user authentication scheme. Browser cross-origin mutations
are rejected. No credentials are returned by these endpoints.

| Method | Path | Input | Output |
| --- | --- | --- | --- |
| GET | `/config` | none | runtime, transport_backend, default_profile, models, driver_running, driver_error, budget |
| GET | `/sessions` | none | `{sessions:[{session_id,title,created_at,latest_run_id}]}` |
| POST | `/sessions` | `{title?:string}` | 201, `{session_id,title,created_at}` |
| GET | `/sessions/{session_id}` | none | `{runs:[{run_id,session_id,query,profile,status,answer,metadata,...}]}` |
| POST | `/sessions/{session_id}/messages` | `{query,model_profile,request_id,dispatch_constraints?:{analyst_review_mode:"required"|"auto"|"off"}}` | 202, `{run_id,task_id,thread_id,session_id,model_profile,status:"accepted"}` |
| GET | `/runs/{run_id}` | session_id, after_event_id=0 | Run identity, complete task list, paginated events, hierarchical scheduling trace, metrics and backend |
| POST | `/runs/{run_id}/cancel` | session_id; `Idempotency-Key` header | Existing H2 cancellation receipt |
| GET | `/runs/{run_id}/artifacts/{artifact_ref}` | session_id, offset=0, limit=16000 (max 64000) | `{content,has_more,next_offset}` from a Run-scoped H2 artifact |
| GET | `/archives` | none | `{archives:[{archive_id,batch,case,query,run_id,status,model_profile,started_at}]}` |
| GET | `/archives/{archive_id}` | after_event_id=0 | `{archive_id,batch,case,readonly,run,view}` using the existing Run/Task/Trace projection |
| GET | `/archives/{archive_id}/artifacts/{artifact_ref}` | offset=0, limit=16000 (max 64000) | `{content,has_more,next_offset}` from that archive's original Run |

Queries are 1-4096 characters. Model profiles must exist in the repository's
metadata-only registry. Each Run freezes a single allowed profile; user selection
affects the next Run, never silently changes an in-flight model.

The optional review selection is frozen in the Root Brief and request hash.
It constrains every Analyst dispatch at every depth; omitted or conflicting
per-dispatch modes are rejected before child creation. Without a Run constraint,
the model chooses and explicitly supplies each Analyst's mode. General tasks
have no Analyst-specific options. Changing the selection on replay is a conflict.

`request_id` is generated by the browser before submission and retained through
ambiguous HTTP failures. The deterministic Run ID plus H2 `run.create` payload
hash makes replay return the same Run. Same key with changed input is a conflict,
not another paid execution. Different request IDs explicitly create different Runs.

Missing/foreign session binding returns 404; invalid input returns 422; existing
H2 state conflicts return 409. Error categories use the existing H2 HTTP mapping.

The Run view includes `trace: {trace_id, spans}`. `trace_id` is the Run ID. Each
Agent Task is a stable span parented to its `parent_task_id`; each Attempt is a
child span of its Task; each physical model request is a child span of its
Attempt. Events remain cursor-paginated in `status.events` and carry their
owning Task span, role, depth, and Agent path when the event belongs to a Task.
Trace metadata includes lifecycle status, timestamps, attempt number, selected
model profile, usage, and bounded error codes; it never includes prompts,
article bodies, credentials, or full model responses.

The same projection is available in exported `scheduling-trace.json`; existing
`events.jsonl`, `model-calls.jsonl`, and `trace.jsonl` remain available with
additive span identifiers. Trace is derived from H2 authority tables and adds
no database table or second scheduler state.

## Persistence

Live and archived views expose additive `review_statuses` entries from accepted
Analyst results, read through Run-bound, hash-verified artifact readers. This
projection requires an accepted Analyst result in the database: ordinary report
text or raw model output containing similar JSON does not establish approval.
The same entries appear in `run.metadata.review_statuses` and on matching Task cards as
`review_status`. No new table or model call is involved. Entries contain the
Runtime review status, label, scope, rounds, draft version, report reference,
Task/objective/result identifiers, and snapshot/scope notices. Missing results
show an explicit empty state; unknown/invalid decisions do not become passed.

Artifact responses add `review_status` and `snapshot_notice` separately from raw
`content`. Review-draft artifacts add a snapshot notice and draft revision. Even
one-character pages receive presentation metadata from the complete verified
artifact; the original bytes, offsets and pagination remain unchanged. This is
a user's read, not an Agent's evidence-consumption event. Reports and Markdown
exports prepend the same status projection and notices, retain the saved answer,
and do not assert that an approved child means the entire Root report passed.

The Test Records tab reads original `*/cases/*/record.json`, per-case SQLite
and exported `scheduling-trace.json` below sibling `runtime-records` (override:
`FINANCE_H2_ARCHIVES`). Archive IDs are opaque hashes of relative case paths;
the browser cannot supply a filesystem path. SQLite is opened read-only without
schema creation/migration; artifact reads retain Run binding, length and hash
verification. Events retain original IDs and page at 200 entries. These reads
do not create live Runs, start archived Workers, call a model, or add research
read-coverage events. Missing records return errors instead of regenerating data.

An archive's `run.status` and catalog status describe execution/delivery, not a
semantic acceptance verdict. Failed and partial child Tasks and Attempt errors
remain visible. The archive view disables model selection and hides message
submission/cancellation. `?archive={archive_id}` restores the same record on a
browser refresh. Archived messages and complete results use the existing renderers;
long artifacts are expanded by explicit paginated reads.

Two UI-only projection tables live in the new H2 SQLite database:

```sql
CREATE TABLE h2_web_sessions (
  session_id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  created_at INTEGER NOT NULL
);
CREATE TABLE h2_web_runs (
  run_id TEXT PRIMARY KEY REFERENCES h2_runs(run_id),
  session_id TEXT NOT NULL REFERENCES h2_web_sessions(session_id),
  query TEXT NOT NULL,
  profile TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  answer TEXT,
  metadata_json TEXT
);
```

These tables do not hold an independent task status. `status`, Task, Attempt,
budget and event data are read from H2 authority tables. `answer` is an idempotent
projection of the terminal Root's complete `result.get(full)` pages. A refresh
does not regenerate it. User result reads are tagged `reader_kind=user`, not
misreported as a main Agent's evidence read.

Run creation commits before its UI mapping. If the UI write fails, retrying with
the same browser key repairs the mapping without creating another Run. Do not
tell users that the HTTP call failed before any execution is possible.

## Lifecycle And Limits

The production module `finance_research_app:app` explicitly enables H2; its
lifespan constructs the repository, adapters and persistent local Workers. Pure
`create_app()` stays as a legacy-compatible test factory. In H2 mode, old
`/companies/.../workbench/sessions/...` execution routes are not mounted.

Separate Workers allow independent tasks to execute while another waits; SQLite
remains the lease/concurrency authority. Dispatcher, recovery and result projection
run independently of browser requests. Disconnecting the browser does not cancel
research. Service shutdown cancels in-flight local execution; standard H2
unknown-outcome accounting and lease recovery still apply, not a promise of
zero duplicate remote charges.

Default storage is `data/finance/h2-runtime.sqlite`; private artifacts and logs
are under sibling `runtime-records/web-h2`. `FINANCE_H2_DB`, `FINANCE_H2_RECORDS`
and `FINANCE_H2_MODEL_PROFILE` are explicit overrides. `H2_REDIS_URL` selects real
Redis. Without it, `fakeredis-local` is visibly reported; no automatic fallback
occurs after an explicitly configured Redis fails. A new FakeRedis process can
lose notifications; persisted Outbox reconciliation republishes work according
to existing H2 lease/republish timers, not by resetting budgets or tasks.

Each browser submission is one independent H2 Run. The session currently groups
research records; it does not automatically inject previous Runs' answers as
evidence into a new Run. Automatic multi-turn context handoff is not claimed by
this entry integration. All prior research is retained in its original Run.
