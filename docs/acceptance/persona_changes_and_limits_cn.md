# 本轮修复、决策与能力边界

执行日期：2026-09-09 至 2026-09-10。本轮只完善已有 Workbench，不改变简历的报告编排、Subagent 调度、Wiki 画像三条主线。

## 一、实际做了什么

1. 设计32条中文用户问题。先分别扮演企业研发用户和个人学习用户，再从开发者视角查输出、Trace及副作用。
2. 使用实际配置的 deepseek-v4-flash，经工作台HTTP接口执行；不以本地演示模型替代真实结果。
3. 为两种身份通过接口创建隔离空间、录入Wiki、更新事实、创建会话；集成用例没有直接向SQLite插入资料。
4. 保留第一次失败、后续完整复测和定点复测的问答、Trace、报告及校验结果，最新逐例汇总不覆盖旧证据。
5. 两位独立子任务分别评审企业与个人场景，另由专门子任务修复Wiki/API、报告分析、政策判断和Trace界面。
6. 使用浏览器实际操作新建空间、Wiki表单、检索、命令选择、对话、Trace和报告。桌面和手机宽度分别检查。

## 三、为什么这样验收

### 报告不是“有HTML就算成功”

必须形成：本轮需求及Wiki事实 -> 范围内来源 -> 中文事件摘要 -> 有条件的影响判断 -> 具体可验证行动。来源URL真实只能证明有这个页面，不能自动证明分析结论成立。

报告允许部分完成，但必须说明缺哪些主题或附件。安全拒绝和无数据诊断分别验收，不计为有用报告产出。个人和企业都至少要有正向报告用例。

### Subagent不是“出现角色名就算成功”

要检查任务来源、允许角色、隔离上下文、实际工具读取、真实模型输出、schema与引用校验、终止原因和主Agent整合。空结果不等于完成复核，主Agent不能把失败子任务包装成成功意见。

显式“分析和质疑两个角度”的用例可能由运行时规划器转为确定性delegate动作，再进入同一个Loop。Trace里的deterministic_action不能宣传为模型自主规划；这批测试证明受控委派可运行，不证明任意问题都能自主分解得最好。

### Memory不是聊天记录的另一份复制

显式长期偏好可跨会话召回；本轮临时要求只依赖历史上下文。Wiki保存是用户的事实编辑操作，不能因为聊天提到Wiki就再次写Memory。

## 四、仍然存在的边界

1. **来源不是全网覆盖**：当前是配置化新闻/技术/论文来源与政策源。GitHub是指定仓库Release，不是任意仓库发现或Trending。
2. **没有可信热度榜**：未接入稳定的星标增长、引用量或点赞采样；不能把最新论文叫作热门论文。
3. **论文主要是摘要**：引用、中文摘要及建议以抓取范围为准，不宣称全文阅读、方法复现或论文结论已被独立证实。
4. **政策可能缺附件**：缺少正式附件及企业触发条件时只能给受限研判，不作完整合规结论。模型不能补编缺失材料。
5. **检索是轻量词项/元数据匹配**：Wiki检索有路径、fact_id、来源与分数；不是大规模向量检索或经过标注集证明的高召回搜索系统。
6. **SSE是实时步骤，不是实时模型token**：正文仍标记buffered_final。断开页面不会立即取消供应方请求，任务在预算内完成并保存。
7. **政策stage尚非全部实时span**：政策路线的事后阶段摘要明确标注记录方式；新闻流程已接实际阶段回调。不能统称所有Workflow均有真实逐stage耗时。
8. **未做生产压测**：32种用户任务覆盖与多次修复回归不能证明高并发、长期可用性或p95 SLO。模型/来源波动仍可能产生部分结果。
9. **没有OS沙箱/生产多租户隔离**：只读工具边界和本地空间隔离不是Docker、操作系统沙箱或成熟账号鉴权。本轮不执行代码、不访问交易/生产系统。
10. **回答仍有编辑质量空间**：部分报告重复引用链条，行动建议和复现条件有时较宽泛。结构校验只覆盖能确定验证的约束，不能代替语义评审。
11. **报告追问是有界投影**：当前读回前两条证据，不等于完整报告候选比较；答案应明确这个范围。全量产物仍可由用户打开HTML查看。
12. **本轮固定Flash**：前端展示真实配置模型，模型凭据从环境配置读取；不把本次验收说成多供应方路由或页面动态新增模型的验收。
13. **真实模型引文仍会失败**：最后补测P04中一条论文分析在初次输出和一次修复后仍未通过逐字引文校验，系统保留partial，不能说三篇均完成高质量中文分析。未降低校验门槛，也未把早先成功那轮替换为最新结果。具体失败与语义判定见结果表。
14. **迁移成本只能作假设**：没有指定目标框架、代码迁移边界及测量时，不能证明“成本高/风险大”或“一步到位”；提示约束已增强，但回答措辞仍须由语义审核检查，不能仅凭schema保证。
15. **建议尚未始终适配轻量学习约束**：P16虽然正确披露最终未入选Eval，但仍把超过1GB输出边界的验证称为只读小实验，未充分区分纸面用例设计、少量样本验证和真实大输出负载。没有实际执行代码或越权操作，但建议质量仍部分通过。

## 五、以后如何复现和解释

1. 打开测试集，从企业默认报告或个人默认报告开始，后续问题保持同一会话。
2. 用问答文档的空间ID、会话名、run_id定位真实页面，不拿另一轮报告替换本轮证据。
3. 展开运行过程，先看Wiki/Memory/Context，再看Workflow或委派，最后核对Artifact和最终回答。
4. 发现错误时，记录预期/实际/对应step/根因/修复/复测，不只写“改了prompt”。
5. 简历保持能力描述；实验次数、耗时、缺陷与边界留在面试讲解中，未经测量不写提升百分比。
