# 金融分析师视角：月度纳指与金银链路复核

日期：2026-09-23 至 2026-09-24。范围：个人金融观察工作空间。评审角色是独立业务审阅子代理，不是持牌分析师认证。

## 1. 先给业务判断

当前能支持：查看已保存行情、复算区间变化、核查公开资料、讨论候选解释和继续追问。

当前不能支持：声称已经查明纳指或金银本月涨跌的主因、给出可执行报价、证明全部价格经独立来源核验、提供可交易的历史因果回测。

本轮不修改通用上下文管理、不增加交易/代码执行权限、不改变其他工作空间的业务流程。金融 Wiki 仅通过公开 API 修改第三方行情源的能力说明，档案升级到 v5，未修改持仓、风险偏好或研究目标。

## 2. 用户问题与真实链路

> 给我讲一下最近一个月的纳斯达克走势和金银走势，帮我分析一下大致的导致的原因呢？

```text
用户自然语言
  -> AgentRuntime / 主 AgentLoop
  -> finance.analyze（普通聊天，不自动发布 HTML）
      -> 固定本轮资产、时间、Wiki 观察偏好
      -> finance.collect：保存原始来源快照
      -> schema / 日期 / 期前基准 / 完整性检查
      -> finance.metrics：代码计算区间、逐日涨跌、日末价极值和回撤
      -> finance.research_audit：时间用途、文章初筛、反向观察、证据缺口
      -> 模型分析：宏观主线 + asset_assessments
      -> 结构契约校验 + 金融语义复核，最多一次修复
      -> 保存 JSON 证据、独立 research_quality
  -> 主 Agent 确认完成：首次分析不再做第二次自由改写
  -> render_chat_analysis：校验状态满足后，由结构化指标/分析确定性生成聊天答案
  -> 后续追问：按需读取 + 数字与口径检查 + 追问语义复核
  -> 确定性来源链接
  -> 答案 / Trace

追问 -> finance.report_read（授权快照，只读、不重新联网）
/report 沿用刚才 -> 现行发布规则再检查 -> HTML / Markdown / JSON
```

## 3. 子代理发现的问题与处理

| 问题 | 本轮处理 | 能证明什么 / 不能证明什么 |
|---|---|---|
| 9/23 讲话被混入截至 9/22 的行情解释 | 逐资产保存发布日期相对行情终点的分类，文章必须声明 historical_context 或 retrospective_review | 日期分类不等于事件与首次公开时间核验；时间顺序仍为 unknown，不认证当时催化 |
| 只贴政策新闻，未检验每个资产 | 逐资产结构化候选机制、引用、反向日期、缺口与历史检验计划 | 覆盖全部资产不等于解释充分；没有证据可以 unidentified |
| 假设说增长，检验却只看利率 | mechanism 与 historical_test 必须匹配，检验窗口必须是实际价格窗口，语义复核再查变量与叙事是否对应 | 字段检查不是完备的自然语言推理证明 |
| done / supported 被误读为原因已验证 | 单独持久化 research_quality；当前因果请求显示 partial / not_established | 数据可用、表述一致、解释充分是不同维度 |
| 日末价最高最低被说成盘中极值 | 窄范围确定性规则检查表头和数值句；生成与 HTML 发布均执行 | 没有新增盘中数据，也没有把日末回撤升级为盘中风险指标 |
| 备用源切换被说成独立核价 | 来源显示第三方供应商，独立价格交叉核验保持 not_independently_crosschecked | 这是纠正表述；多源核价本身尚未实现 |
| 用户无法点开价格或资产解释来源 | 从保存证据生成链接，合并主线与逐资产引用，HTML 每个资产列出其依据 | 有链接不等于整段主张正确，仍需检查原文 |
| 无关监管讲话堆成宏观主线 | 宏观主题标题初筛、翻译去重、记录排除原因；全部原文仍保留附录 | 标题初筛可能漏检，不宣称语义召回完备 |
| 金银价格对应 8/24，却被说成 8/25 基准 | 每页只读证据均带 return_basis；明确资产基准日期的正文/表格规则拒绝已知错误 | 规则覆盖明确表述，不是任意自然语言的完备验证 |
| 区间跌幅被混作回撤排名，震荡被概括成单边 | 根据确定性指标检查已知的回撤排名和单边措辞 | 不宣称已证明全部子区间形态；复杂模式仍需专门指标 |
| 补查第四页证据被三次工具上限阻断 | 金融循环单工具上限调整为六次，总循环预算仍有限；采集仍每轮最多一次 | 只读授权与禁止重新获取仍执行，没有扩大工具权限 |
| 模板把期后资料一律说成无解释价值 | HTML 改为可用于事后回顾，不能仅据此认证当时催化；追问规则检查绝对否定 | 回顾价值不等于当时已知，更不等于因果被证实 |
| 复核员只收到目录/引文，误称正文不存在 | 按被引来源传入最多 6000 字的已保存正文，保留字符数和截断标记；目录告知可只读展开 | 已保存正文、当前可见摘录、全文完整性认证是三回事；没有声称已人工校对全部网页 |
| 追问把负向折现假设改成加息推动纳指上涨 | 对已保存的 rates_discounting 机制方向增加窄范围主张检查；价格反向波动不得用于证明驱动不同 | 对明确已知错误进行拦截，不宣称可以用正则表达式证明任意金融论述 |
| 日线工具的累计涨幅被误作单日涨幅 | 只读工具将累计字段显式命名 cumulative_change_from_baseline_pct，与 daily_changes 分离；检查日期及明确逐日/连涨语境中的百分比 | 保存的原始快照不改；只调整工具投影，不让模型替代数值计算 |
| 正确的结构化报告被主 Agent 二次改写出错 | 首次分析由 render_chat_analysis 交付：基准/期末、涨跌、极值、回撤由代码排版，业务分析沿用已校验字段，不再做第二次自由创作 | 主 Agent 仍决定是否调用工具；没有跳过分析阶段的 Schema/事实语义验证。新增 validated_analysis_projection 审计记录，不冒充新增模型复核 |

## 4. 核心契约怎么学

1. `domains/finance/research_audit.py`：先看 audit，再看 validate_assessments。它是代码执行的业务约束，不是让另一个 LLM 说“通过”即可。
2. `domains/finance/schemas.py`：AssetAssessment 包含 mechanism、document_uses、counter_observation_dates、historical_test。
3. `domains/finance/workflow.py`：看工具如何过 ToolGateway、结果如何进入分析、失败如何阻断发布。
4. `domains/finance/answer_verifier.py`：区分确定性数字/口径规则、模型语义复核、来源交付三件事。
5. `domains/finance/report_reader.py`：追问可读 research_audit，但不能跨会话任意读取或重新采集。

其中 historical_test 是待执行的研究计划，不是已经跑过的回归模型。假设属于增长盈利，检验就必须围绕增长/盈利等变量；未来价格不能倒证本月的历史原因。反向日线是实际观察，不是宏观机制被证伪的充分条件。

## 5. 验收问题

- M15：原始月度纳指与金银问题。
- M16：沿用刚才的数据，不重新获取。请列出这三个资产的计算起止日期、基准价格、期末价格和涨跌幅，并说明金银的采样口径与来源。
- M17：沿用刚才的数据，不重新获取。哪些原因还只是猜测？请分别说说纳指、黄金、白银的证据缺口，以及报告期内有哪些反向表现需要注意；晚于行情截止的文章能解释此前涨跌吗？
- M18：/report 将刚才的分析生成HTML报告，沿用那份快照，不重新获取。保留逐资产核查、来源链接和未证实的原因说明。

验收不只看 HTTP 200：检查资产与时间是否正确、期后文献是否错当催化、逐资产是否漏项、反向日期是否来自数据、检验计划是否对应机制、追问是否重新获取、HTML 是否保留质量边界和来源、Trace 是否记录审计工具与门控。

调试记录保留在 `data/acceptance/analyst-audit-round1-20260923.json`、`analyst-audit-round2-20260923.json`。第一轮确实漏掉了最高最低口径；第二轮仍有假设/检验错配和无关讲话，不将这些运行冒充最终业务通过。

`data/acceptance/analyst-audit-final-20260923.json` 虽然文件名为 final，实际未通过：M15 单边与回撤排名误述，M16 金银基准日期错误，M17 被三次工具读取预算阻断。保留失败证据，不作为交付通过依据。

`data/acceptance/analyst-audit-corrected-20260924.json` 四轮均返回，但仍存在“黄金一路走低”和期后文章绝对否定等业务表述缺陷，不能只看 HTTP 200 判通过。

跨北京时间午夜后，“最近一个月”请求窗口随当前日期移动：9/23 测试期前基准为 8/24，9/24 测试期前基准为 8/25。不能将不同快照的收益率差异解释成算法优化效果，也不能混用两个窗口做验收。

`analyst-audit-reviewed-20260924.json` 曾被新规则误拦“削弱单边叙事”这一否定表述，已经补充否定测试；该轮不通过。

`analyst-audit-delivery-20260924.json` 暴露正文复核缺失；`analyst-audit-evidence-20260924.json` 修正了这一点，但子代理仍拦出机制方向改写及过度解释。文件名并非验收结论，不将这些运行算作业务通过。

`analyst-audit-acceptance-20260924.json` 仍有“一路走弱”的绝对化修辞；`analyst-audit-release-20260924.json` 发现连涨列表混入累计百分比。已按上表修复工具字段歧义与明确逐日数值检查，不抹除这些失败。

`analyst-audit-checked-20260924.json` 仍出现主 Agent 将窗口首日价格与期前基准收益混列，并把局部高点说成窗口最高。这证明继续罗列措辞规则不够，必须分离数值事实交付与自由语言生成。

最终调整：首次分析不再重复写作，直接展示已经验证的结构化结果；后续追问仍保留按需读取与复核。投影只在 data_status=done、analysis_status=done、analysis_verification.supported=true 且 issues 为空时允许，否则不发布。测试证明未通过分析不能借渲染旁路发布，前端答案与持久化分析保持一致。

最后复验：`data/acceptance/analyst-audit-projection-20260924.json`。验收分为链路完成、数值口径、解释证据三个维度，不将前两个通过等同于第三个充分。

## 6. 尚未解决的真实业务依赖

- 同区间美元、名义/实际国债收益率、政策预期与意外部分。
- 纳指成分/行业贡献、盈利预期与资金流；金银供需、ETF/库存等数据。
- 不同供应商在相同品种、日期和报价基准下的独立交叉核价。
- 带时分、时区及首次公开信息的事件窗口；若研究盘中冲击，还需要盘中行情。

本机探测 FRED 历史 CSV 超时，尝试的 Treasury 旧 XML 入口返回 404，没有将这些数据写成已接通。浏览工具能读取官方说明，不代表本项目的采集器已能稳定取得完整序列。后续接入应使用带单位、时间、完整性和缺失状态的独立驱动数据契约，而不是把收益率塞进股票 OHLC。

官方方法/口径参考：[FRED 实际国债收益率 DFII10](https://fred.stlouisfed.org/series/DFII10)、[FRED 广义美元指数 DTWEXBGS](https://fred.stlouisfed.org/series/DTWEXBGS)、[BullionVault 黄金参考价说明](https://www.bullionvault.com/gold-price-chart.do)。广义美元指数不是 DXY，批发现货中间价不是可执行报价。

结论：本轮提高的是证据约束、复核与交付透明度。缺少真实驱动数据的问题不能靠增加一个 Skill、修改 Wiki 或多跑一个子代理解决。

## 7. 建议的下一步业务设计

优先级不是增加更多角色，而是补齐有明确验收契约的数据：

1. 驱动序列工具：美国名义/实际国债收益率、明确定义的美元指数。必须带频率、单位、观察日期、发布/修订时间和缺失状态，不能塞进股票 OHLC 冒充同类指标。
2. 事件窗口核对：提取原文公开时刻、时区与首次披露来源，对齐行情窗口；区分实际政策动作与市场预期差。只有日线时不做盘中冲击结论。
3. 独立价格核验：只比较相同资产、报价口径和日期的独立来源；供应商 failover 不能算交叉核验。
4. 贡献解释：纳指需要成分/行业贡献，白银需要供需与库存。缺这些时只交付观察和可检验假设，不能输出买卖指令或持仓盈亏。

本轮尚未接通上述新增外部数据，不把设计建议写成已经实现。已有金融专用工具 `finance.research_audit` 完成的是输入证据审计，不是已经执行历史回归或因果识别。
