范围：模型公共动作 JSON、工具参数校验、补正诊断、H2 调度回归。  
不包含：金融语义质量、真实 Redis、商业化并发稳定性和待确认的自动收尾策略。金融 Root 可选状态增量已按 026/028 实现，不应整体标记为未定义。

## 结论

本轮确认：JSON/动作协议的常规技术稳定性已经完成一个可运行的 MVP；没有证据表明当前 H2 调度底座因 JSON 解析而整体不可用。新增的修复不会改变 ArticleCard、浅读/深读、证据分析、外部核查或模型选择策略。

## 技术问题归因

| 类别 | 具体问题 | 归因 | 处理 |
| --- | --- | --- | --- |
| JSON 字符串语法 | 字符串内裸控制字符、非法反斜线导致完整动作拒绝 | 模型公共输出的常规语法问题 | 已修复：完整终态内做有界字符串修复，随后仍严格解析 |
| JSON 结构 | 缺括号、首对象截断、自然语言前缀、数组冒充对象 | 协议结构错误，不是可安全猜测的局部问题 | 保持拒绝，走一次同模型结构补正；083 已批准无围栏时只执行首个完整对象、丢弃其尾部，围栏内多对象仍拒绝 |
| Trace 诊断 | 丢弃尾部中的坏字符串被统计为动作修复，尾部长度受修复膨胀影响 | 083 与 087 组合后的技术缺陷 | 088 先复现、后修复；不改变执行对象或金融语义 |
| 工具参数 | 参数类型、未知字段、越权工具或未知引用 | 模型动作与工具契约不匹配 | 保持严格 Schema/权限校验，结构化反馈给模型 |
| 流式输出 | 尚未收到终态时出现局部 JSON | 流式预览与可执行动作边界混淆 | 只收集完整终态，截断流不可执行 |
| 补正 | 模型首次动作不合规 | 模型契约遵守率问题，不应回灌整段拒绝正文 | 保留原始输出，隔离错误诊断，一次补正；首次补正传输失败可按既有边界重发一次 |
| 证据绑定 | 证据引用、跨文章推断或条件被写错 | 金融语义/模型推理问题，不是 JSON 解析问题 | 不放宽 Schema，不把格式成功当作语义正确；保留 partial、warnings 和原文证据 |
| 传输 unknown | 中转站、网络或服务端使一次请求结果未知 | 环境/传输问题，不能归因于 JSON | 按现有账本和一次补正传输重发边界处理，不自动换模型或扩额 |

## 采用的 MVP 机制

动作解析现在分成四层：

1. 收集完整 provider 终态，保留原始模型输出。
2. 只对 H2 `agent_action.v1` 的 JSON 字符串字面量做有限规范化：裸控制字符转义；非法反斜线转为字面反斜线。字符串外结构不修复。
3. 使用标准 JSON 解析，再执行 `AgentAction`、工具参数、权限和金融结果校验。
4. 非法结果以结构化失败进入已有补正/审计链路；不从任意自然语言中猜动作，不补括号/引号，不执行半截 JSON。

这对应 [Pi Agent 固定源码](https://github.com/badlogic/pi-mono/blob/fbc456d827d7a4a951c50e7145af066226e2f8e9/packages/ai/src/utils/json-parse.ts)的“字符串字面量有限修复、终态仍严格解析”，以及 DeepSeek Harness 的[参数解析](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/core/agent-loop/src/tool-calls.ts)和 [Schema 校验](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/core/tools/src/schema.ts)分层。项目没有引入 provider-native Function Calling；083 的首对象边界、065 的隔离补正和 073 的正文冻结属于本项目策略，不冒称来自这些框架。
