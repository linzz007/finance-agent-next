# 共享数据源改造与双 Wiki 实测

日期：2026-09-10。模型：通过本地应用调用配置中的 `deepseek-v4-flash`。测试结果不等于性能宣传；未测量准确率提升、生产稳定性或业务收益。

## 1. 本次修改

1. 两个 Wiki 使用同一份 `config/sources.json`，公司名称是分析背景，不是抓取目标。未添加同花顺官网专属采集器。
2. 将自然语言与 Wiki 默认值解析为 ReportRequest：研究对象、主题、时间、时区、数量、来源限制、Wiki 引用、配置版本与资源预算。
3. 用一次受限规划生成公开检索词与主题规则。模型不能改来源白名单、日期和预算；模型失败保留诊断并回退规则，不拿其他任务的快照或测试数据冒充。
4. 启用 17 个共享入口，覆盖官方技术发布、GitHub、arXiv、政府政策、媒体与新闻搜索。单源候选上限 40、合并候选上限 500；这是上限，不保证每个源都有 40 篇可用新资料。
5. 先在采集阶段处理格式、日期与来源，再合并二次清洗：规范 URL、重复内容、来源链、明显垃圾标题与数量预算。相同标题但不同内容不直接合并。
6. 为静态来源增加短时缓存；成功/部分成功及403/429限流退避为300秒，总体临时失败仅冷却30秒，任务快照不得延长错误缓存。GitHub 补充 API 失败保留已读 Atom 线索，缺可信发布日期的线索不能当本周发布内容。
7. 政策页面读取正文区，去除导航和页脚；单篇失败不丢弃同源其他成功条目，失败 URL 与原因留在诊断中。
8. 完整报告保留中文摘要、Wiki 事实、条件性影响、逐项建议与来源附录；聊天只输出紧凑摘要并链接 HTML。不会用固定论文建议模板替换模型的逐项建议。
9. 追问读取本会话、本工作空间的报告产物，保留日期、来源摘要和已校验分析；区分原文事实、模型分析、全文未读与热度未知。
10. 修复 Trace 的模型调用与来源汇总：确定性动作、真实 provider 逻辑调用和 HTTP 尝试分开；未记录的计数标为未知，不写成零。
11. 修复英文事件关联不到中文 Wiki 的问题：用已命中主题的中英文词扩展检索，记录扩展词和选中 fact_id；检索仍只返回真实 Wiki，不把相关性推断当成公司采用事实。

## 2. 来源范围与限制

| 类别 | 已配置入口 | 证据边界 |
| --- | --- | --- |
| 官方技术资料 | OpenAI News、Hugging Face、DeepMind | RSS 摘要不等于完整正文；需通过内容门控 |
| GitHub | 公共仓库发现；Claude Code、Codex、LangGraph、MCP、Hermes、EvoAgentX Releases | 未认证 API 可能限流；补充失败与缺日期显式记录，不编造发布日期 |
| 论文 | arXiv 公开主题查询 | 当前读取元信息和摘要，不代表全文阅读、实验复现或热门程度 |
| 政策 | 网信办列表、网信办已配置政策页、工信部已配置政策页 | 列表范围有限；固定旧政策不因本次抓取变成新发布 |
| 新闻线索 | TechCrunch AI、The Verge AI、Google News 主题查询 | 聚合标题和二手线索不能直接当作主要结论依据 |

证监会候选入口本轮没有启用：验证得到旧列表与旧正文，页面生成元数据却包含新日期，且正文结构尚不兼容。不能把 HTTP 200 当作合格数据源。新增 Wiki 不会扩大这些平台的覆盖范围。

## 3. 测试方法

- 通过公开 HTTP API 创建两个隔离测试工作空间、录入 Wiki 和创建会话，没有直接向数据库塞业务数据；用户原有 Wiki 未被覆盖。
- 共 14 个中文用例，包含普通聊天、两个默认报告、报告追问、相同专题覆盖不同 Wiki、自然复杂任务、虚构收益断言、官方政策限定和未来时间窗口。
- 保存每次 query、answer、请求参数、来源快照、Markdown/HTML、RunArtifact、完整 Trace 与逐项检查结果。
- 机械检查覆盖 SSE、会话归属、Wiki 未被改写、报告字段、共享来源配置、时间边界、模型规划调用、清洗计数与产物可读取。
- 独立子智能体另做内容与 Trace 审阅；允许判定部分可用或不通过，不能把 HTTP 200/报告存在当作业务质量合格。
- 整个任务只使用并复用 3 个子智能体，没有超过用户规定的 5 个。

## 4. 测试中发现并修复的问题

| 观察到的问题 | 修改 | 验证边界 |
| --- | --- | --- |
| GitHub 补充请求 403 后，已经读取的 Atom 也被丢弃 | 保留线索，标记 partial 与缺日期 | 不等于解除 GitHub 限流 |
| 政策导航进入正文，修正文区后又因一篇失败丢弃整个源 | 显式正文选择器、逐篇错误隔离 | 只验证已接入页面结构，不承诺所有政府站点 |
| 一个事件返回多条同 ID 分析，修复后仍残留无归属错误 | 明确事件数量契约，按 event_id 记录与清除修复错误 | 唯一 ID 不代表语义必然正确 |
| 模型的条件句没有“可能”就被误判 | 支持若/待核验等明确限定，仍拦截保证收益表述 | 规则不是完整语义证明器 |
| 论文建议被固定模板悄悄替换 | 保留并校验模型逐项建议 | 仍要人工检查具体性和可执行性 |
| 请求已说从反馈改进 Agent，关键词回退却匹配到硬件内存论文 | 增加反馈改进主题识别、业务限定词和回归用例 | 主题过滤仍有漏召回风险 |
| 聊天透传大量原文，报告追问却只看到一句短引用 | 分开聊天摘要、报告产物与受预算约束的回读证据 | 摘要回读不冒充重新联网或读取全文 |
| Trace 来源全零、模型逻辑调用少计 | 从实际工作流结果和 provider 元数据对账 | 缺失的尝试数仍明确未知，不推算账单 |

- `shared_discovery_initial_20260910`：首轮 4 条机械通过，独立审阅发现企业默认报告不合格、个人报告部分可用。
- `shared_discovery_final_20260910`：14 条机械通过，12 项条件性检查跳过；后续人工审阅发现规划格式、专题误选及追问证据截断问题。因此目录名 final 不代表已签署质量验收。

### 未通过或未覆盖

1. 企业业务与政府政策覆盖仍有限：默认报告只找到1项实质材料，政策限定任务不能证明已覆盖所有有效规则。不能用于完整合规判断。
2. 最后默认报告17个来源中10个成功、7个部分受限；GitHub未认证API限流仍在。修复降级逻辑不等于来源稳定性问题消失。
3. 复杂实验建议仍需人工检查，尤其是改动粒度、样本量、预算和指标含义；不把模型输出当作已验证的实验方案。
4. 这些自然问题未稳定触发真实 Subagent，不能凭本批结果声明自主委派已验收；离线测试通过与真实委派发生是两回事。
5. 没有测生产并发、长期连续运行、全网召回率、论文热度和业务收益。本轮主要验证数据探查、报告与追问链路。

## 6. 如何看结果

最新默认报告证据目录是 `data/acceptance/shared_discovery_release_20260910`。先看其中 `cases/SD03/answer.md` 与 `cases/SD04/answer.md`，对比同一句 `/report 生成一份报告。` 的主题与建议；再打开对应 `01_html_report.html` 查看来源附录。

沿 `trace.json` 查看 Wiki/Context、`report_discovery_plan.v1`、五个 Workflow 阶段、分析/修复调用、Gate、HTML 产物和最后回答。`02_run_artifact.json` 保存任务参数、采集状态、清洗计数、入选与未覆盖主题。

自然复杂问题不保证委派。如果主模型直接回答，只能说验证了主循环的直接回答路径，不能把它算成 Subagent 已触发。
