# 全球宏观观察：本轮交付与验收

日期：2026-09-23。工作台：http://127.0.0.1:8503/ 。选择「个人金融观察」。

## 1. 本轮交付了什么

1. 在原有 Workbench 中加入全球宏观行情分析，不建立第二套聊天系统；企业与 Agent 研究空间保留。
2. 金融 Wiki 已通过公开 API 更新为黄金、白银、标普500、纳斯达克综合、道琼斯五项关注范围。档案仍是待确认草稿；历史持仓不是当前持仓，未计算私人盈亏。
3. 普通聊天可调用 `finance.analyze` 获取数据、计算与分析，但不发布 HTML。明确的自然语言报告请求和 `/report` 才发布报告。
4. 追问使用会话授权的 `finance.report_read` 回读指标、原文、分析与品种证据。已通过校验的分析可直接转 HTML，复用原始快照，不为换格式重新抓行情。
5. 所有路径保留 Runtime、Context、ToolGateway、Gate、Trace 与产物关联，没有把模型答案直接当成可发布报告。
6. 后台 Worker 每60分钟采集一次，只读公开来源并保存快照，不自动调用付费模型或推送报告。开关与进程存活状态分别展示。

## 3. 实际链路

```text
用户输入 -> Runtime / TurnCoordinator -> 当前 Wiki 与会话上下文
  普通行情问答 -> Main AgentLoop -> finance.analyze
  明确报告请求 -> /report Skill -> report_workflow.run
    请求与画像固定 -> 采集快照 -> schema / 交易日 / 单位校验
    -> 确定性指标 -> 中文分析 -> 引文校验 -> 语义复核 -> 发布门控
  追问 -> finance.report_read -> 只读本会话授权快照 -> 回答复核
  原分析转报告 -> 校验旧快照与分析 -> finance.publish（不重新采集）
-> AgentRun / AgentStep / Trace -> 聊天回答及报告产物
```

报告主流程是固定工作流，由主循环承载。它的分析复核调用不等于创建了新的 Subagent；本轮独立验收的开发助手也不是应用内部的子角色。不能把这三者混为同一个功能。

## 5. 修复记录

| 发现的问题 | 修复方式 |
| --- | --- |
| 今天行情混成最近一周行情；当天尚未收盘误判缺失 | 分离行情/资料窗口；保留请求截止日并计算已完成市场日 |
| 画像支持五资产，单问黄金被复核器认定少了四项 | 复核传入本轮request与observed_symbols，能力范围不等于请求范围 |
| “不要用期货”吞掉“生成报告”；“别做报告”误路由 | 对报告动作判定否定范围，覆盖自然语言与斜杠入口 |
| 英文摘录句首大小写误判伪造 | 只归一大小写与空白匹配，保存真实原文跨度；改句意/数字仍拒绝 |
| 给了原文标题却没链接；金銀行情链接被宏观目录误拒 | 在授权observation中核对URL，覆盖article/source_url/evidence_urls |
| 追问把原本未知的因果改述成已归因 | 原因/反证追问先读取保存的analysis；复核加入预算后的会话历史 |
| 窄幅、分化被写成“没有共同宏观冲击” | 主Prompt和复核明确正向、否定因果都需证据，不接受末尾免责声明免责 |
| 原始feed字段、适配器分类和20分钟系统缓冲混淆 | 返回明确provenance，禁止把内部描述写成来源自述 |
| 日线被误说可判断盘中/尾盘 | 工具声明daily_close_only_no_intraday，复核按实际粒度限制结论 |
| 复核失败继续空转或旧partial升级成功 | 有界修复与终止；旧快照再次过发布门控，不修改原报告 |
| Wiki引用只有空锚点 | 保存真正被引用的事实快照并渲染附录；旧报告缺少快照时明确披露 |

失败轮次没有删除或改成成功。真实测试是迭代过程，不能挑最后几条成功结果计算“100%稳定成功率”。

## 6. 怎么看 Trace

工作台左上切到「个人金融观察」，打开验收会话。回答上方展开「运行过程」，看工具与门控详情。

- 普通行情：`finance.analyze` 的输入、采集快照、metrics、analysis、verification；不应出现HTML发布。
- 报告：固定profile/acquisition/validation/metrics/analysis/publication阶段；检查真实源状态，而不只看运行done。
- 追问：`finance.report_read` 的report_id、section和observation；不应出现新的finance.collect。
- 转报告：新的report_id与旧snapshot/metrics/analysis一致；应只有授权发布，无新增金融分析。
- 单次证据 API：`GET /companies/finance_observer/workbench/sessions/{session_id}/runs/{run_id}/trace`。

Trace描述怎么执行；报告Artifact是可阅读成果；JSON快照保存来源与分析证据。三者通过run_id/report_id/snapshot_id关联，不是同一个东西。

## 8. 长期使用边界

- Worker需独立进程持续运行；机器休眠、关机、进程退出不会采集。当前没有安装开机自启或云端托管。
- 每小时采集不代表小时级K线，底层仍是已完成日线与有界资料抓取。
- 公共行情接口无服务可用性保证；缺少完整核心数据时拒绝发布是必要保护，不算正向任务已完成。
- 当前能做市场概览、证据核查和条件解释，尚不能承诺稳定找出当天真实催化。尤其缺美元/收益率/成分数据时，须承认原因未知。
- HTML与保存的报告不可变。后续刷新生成新版本，旧报告不会随Wiki修改而悄悄改写。
- 离线测试与本轮少量真实请求不是压力测试、长期稳定性或投资绩效证明。没有编造收益、延迟提升倍数或服务SLA。
