## 实现结果

Runtime 从 Analyst 最终结果的结构化 review 记录生成当前状态，放在被核验的
result/review_targets 之外。主 Agent 完整取得结果后，将状态单独保存进检查点，
并在后续 child_review_statuses 上下文中收到。未读完分页不登记，不扩大证据权限。

实时/归档报告、任务树、资料阅读和 Markdown 导出使用相同状态投影，显示核验范围、
轮数、草稿版本与报告引用。已接受的 Analyst 结果必须有数据库角色与引用关联；
普通报告或原始模型输出即使包含同名 JSON，也不能制造通过结论。
通过状态还要求 verdict=passed、有草稿版本及报告引用、无阻塞项。

原始正文和 limitations 保留，阅读时注明快照时点。外部事实尚未独立验证等真实限制继续保留。
新规则加强 Analyst、Verifier 和 Root 的文字要求，并精简 Analyst 的重复指令；旧 Run 继续自己的冻结规则。
结果改动仍触发完整哈希检查和必要复审，五轮上限、模型、费用和时间预算不变。

## 结论与边界

本轮通过的是“当前核验状态由记录生成、跨界面和父上下文一致”的工程检查。
模型自由正文仍可能产生过期描述；当前通过明确的快照说明和独立状态避免将其当作最新事实，
没有宣称 Prompt 能保证每句话正确。新的 Verifier 提示词能否稳定发现此类文字，尚未新增真实模型验证。
单个子结果在指定范围内通过，不等于所有外部事实或整份主报告都通过。
