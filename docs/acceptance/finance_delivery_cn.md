# 金融观察扩展：试用与验收

日期：2026-09-23。结论：**本轮金融报告与多轮追问链路已跑通，独立审查限定通过。** 本文记录实际实现、运行证据和适用边界，不代表任意金融问题或全部网络来源都已验收。

## 1. 怎么试用

1. 打开 `http://127.0.0.1:8503/`。
2. 左上角选择 **个人金融观察**，不要选同花顺或 Agent 自进化。
3. Wiki → 金融观察档案：已有可编辑的草稿，默认观察中国宏观、A股主要指数、机构公开观点；持仓未知，未推断你的资金或风险偏好。
4. 对话页打开 **验收示例 · 金融观察报告与追问**。报告回答下方可打开 HTML、Markdown 和运行产物；点击“运行记录”，再展开“运行过程”查看本轮 Trace。
5. 后续可修改 Wiki 的观察目的、市场、主题、指数、天数、约束。更改档案不会篡改旧报告；新报告保存新的档案版本。

可直接复制到新对话的例子：

```text
/report 请结合我的金融观察档案，生成2026-09-01至2026-09-22的金融观察报告。包括上证指数、沪深300、创业板指的区间表现，以及本期官方宏观发布和机构公开观点；说明和我的学习关注有什么关系，区分事实与解释，附上来源和数据日期。没有的数据请明确标注。
```

这组明确日期用于复现本次验收。日常可换成“最近一周”或“最近30天”；当天收盘尚不可得时不能保证“今日行情”，会保留实际交易日及缺失说明。

继续在同一会话追问：

```text
刚才报告里沪深300的区间涨跌是怎么算的？请列出基准日、截止交易日、两个收盘价和公式，并说明这是不是实时行情。

基于刚才报告，我接下来最值得关注哪两件事？请分别讲事实依据、可能的另一种解释和还缺什么证据，不要给我买卖建议。
```

## 2. 本次完成了什么

- 保留原项目及原来的两个空间，新增金融观察空间；通过后端 API 创建和保存，不直接塞数据库。
- 增加版本化金融档案、Wiki 展示和检索索引；表单带草稿状态与版本冲突检查。
- 新增金融数据契约：指数日线、文章、来源状态、快照、报告。价格、日期、重复记录及跨空间读取均有校验。
- 接入腾讯日线及备用提供方、统计局中英文发布、Fed/BIS 机构讲话；保存 URL、发布日期、获取时间、正文及内容 hash。
- `/report` 复用原 AgentLoop，嵌入六阶段金融 Workflow：画像/请求 → 采集 → 质量校验 → 指标 → 中文分析 → 发布。
- 用代码计算价格指数区间变化、峰谷、最大回撤、连续上涨天数和同口径排名。模型不负责心算这些指标。
- HTML 展示摘要、指数曲线、变化解读、关注项、来源及边界；引用可定位原文。
- 普通对话可读取同会话授权报告的日线、指标、来源目录、原文及分析；只读旧快照，不冒充重新联网。
- 报告和追问增加引用/事实复核、受限修复次数及 Trace；失败不冒充已完成分析。
- 后台 Worker 持续采集公共数据；SQLite 保存运行状态、下次任务、失败重试及历史快照；支持暂停/恢复。
- 修复前端 Markdown 标题与链接解析，来源原始 JSON 默认折叠；金融 Wiki 在桌面和窄屏检查无重叠。

## 3. 运行链路在哪里看

报告 Trace 应有以下内容：

| 阶段 | 要看什么 |
|---|---|
| 画像和请求 | 原问题、明确起止日期、指数代码、Wiki fact IDs、档案版本 |
| 采集 | `finance.collect`、快照 ID、各来源状态、实际获取时间 |
| 质量校验 | 时间/类型校验、缺失来源、是否允许带缺失说明继续 |
| 指标 | `finance.metrics`、基准日期、公式和可复算的收盘价 |
| 分析 | 模型输入证据、中文结构化输出、引文及逐项语义复核结果 |
| 发布 | `finance.publish`、HTML/Markdown/JSON 产物路径 |
| 追问 | 授权 report_id、`finance.report_read` 的参数和 observation、证据/事实门控、最终回答 |

Trace 是“怎样得到回答”的运行记录；Artifact 是“这次保存了什么”的不可变报告及证据。Worker 定时采集没有模型决策，因此使用自己的任务/快照记录，而不是虚构 Agent Trace。

## 5. 测试中修复的实际问题

| 问题 | 修复 |
|---|---|
| 上下文只投影少量内容，回答把未展开误当未保存 | 加报告可用数据目录和分页只读工具；判断缺口前检查证据 |
| 模型混淆涨跌排名、连续上涨和最大回撤 | 代码计算各项指标并提供明确口径，保留失败快照作回归 |
| 修复模型未拿到上一版候选 | 完整候选与具体问题一起反馈，不只给截断错误句 |
| 复核说明“成立”，全局状态却失败 | 逐项 reason/verdict，由代码汇总；缺项/重复项拒绝 |
| Anthropic 兼容接口把门控反馈移到开头 | 使用保持时序的 Runtime observation，避免重复 final 耗尽预算 |
| 日期、真实观测日数量被当成金融数值误拒绝 | 日期格式回归；数量按证据记录验证，保留金融数字约束 |
| 缺失/损坏报告仍可能调用复核模型 | 证据装载先校验，失败直接拒绝且不花复核预算 |
| 当月与累计宏观口径被泛化 | 增加逐指标口径要求、标题统计期提示与复核 |
| 原始来源 JSON 占满页面、Markdown 链接被截断 | 默认摘要+折叠技术详情，修复解析并加前端回归 |
| 金融报告已采集，Trace 顶部却显示数据源未记录 | 从金融 acquisition/validation 阶段汇总快照、状态和数量，区分部分成功与未记录；不改历史报告内容 |

## 6. 当前边界

- 这是可用的金融观察扩展，不是生产级行情终端或投资顾问。文章是有限公开样本，不声称覆盖全网/全部机构。
- IMF 入口实测 403，明确未接入；没有券商付费研报、账户同步、交易、FRED 数值库。
- 暂只支持配置中的境内价格指数。不支持的资产或日期应明确拒绝，不偷偷换成默认指数。
- 没有完整交易所日历校验、成交量单位统一、分红再投资口径；原始量字段存在也不能擅自解释为成交额。
- Wiki 是稳定档案，行情与文章自动更新在快照中。不会根据市场上涨自动修改风险偏好；结构化档案目前通过表单/API 显式修改，不自动将普通聊天写入金融档案。
- Worker 每60分钟采集，但不自动调用付费模型生成日报。电脑关闭/进程退出就停止；当前未配置开机自启。
- Schema、确定性计算和模型复核各自保证不同边界。有限用例通过不等于任意问题都不会出错，金融结论仍需要核查来源。

## 7. 以后如何重启与复验

在项目目录运行：

```powershell
py -3 run_policy_api.py --port 8503
```

另一个终端运行采集 Worker：

```powershell
py -3 scripts/run_finance_worker.py --company-id finance_observer --interval-minutes 60
```

API 脚本读取本地 `.env.local`。不要把 API Key 写入 Wiki、报告或测试说明。Worker 只采集，不需要模型密钥。

```powershell
py -3 -m pytest -q
node --test tests/test_finance_wiki_ui.mjs tests/test_markdown_ui.mjs tests/test_workbench_wiki_ui.mjs tests/test_workbench_trace_ui.mjs tests/test_trace_source_summary_ui.mjs
py -3 scripts/harness_linter.py
py -3 scripts/run_finance_acceptance.py --label finance-recheck
```

最后一条会真实调用模型，默认测试“最近30天”，结果保存到 `data/acceptance/finance-recheck.json`。独立复核参考 `finance_independent_review_cn.md`。
