# 金融 Agent 真实查询验收（2026-10-13）

## 口径

- 权威设计：飞书文档 `LiE7dgP6SoHR6IxKXZ0c5qkWnHh`，revision 168，尤其第 13 章；查询集与分层验收标准见 `docs/finance_agent_eval_v1_acceptance.md`。
- 本轮使用当前代码、真实模型和真实工具；每题独立会话，各运行一次。原始答案和 Trace 摘要保存在 `data/finance_eval_v1_acceptance_20261013/Q*.json`。可通过 `session_id` 回查完整 AgentStep。
- 耗时从当前工作树直接调用 `ChatWorkbenchService` 测得，不含浏览器渲染，也不证明 8503 端口上的既有服务进程已加载本轮代码。
- 验收期间独立网页工具回访美联储页面失败；Q22 对官方来源的核对依据本轮 Agent `web.open` 保存的页面原文快照，不把它称为第二次独立网络核验。
- 分别判断内容、证据、Trace。`delivery_status=done` 仅表示已送达，`audit=accept` 也不等于事实正确。本轮是代表性抽查，不是 30 题全集或延迟分布统计。

## 逐题结果

### Q01：简单查值

- Run `4a62e4d273b047d0bdf7f890cc723827`。答案给出 5 位作者、888 篇及最新日期；与本轮 `article.list.authors` 中的 137、66、275、281、129 篇及最新发布日期一致。未声称读过正文。内容、证据、Trace 的基础要求通过。
- 为得到作者汇总，`article.list` 同时向模型返回了 500 条文章候选；Trace 有 5 次 `context_offload`。简单查值仍用了 12 个模型节点和 40.59 秒。这个路径的上下文开销与问题规模不相称。

### Q04：单篇深读

- Run `9cd5ddbf88404021b51861e8495c65f8`。TT 2026-09-30 文章被完整读取（L1-L63），并生成 1 张 ArticleCard。答案区分了作者提出的清算/人为砸盘解释、行情能支持的价格变化、未核实的 Jane Street 数字和未到期的预测；研究稿保留完整。
- `review_targets` 实际有 3 个，但目标审核的模型响应多次缺少要求的 `output` 包装；Trace 有 3 个失败的 `finance_target_answer_audit.v1` 模型节点，没有 `finance_review.normalize.v1`。最后状态是 `review_failed_full_draft`，未完成目标审核。约 12 个目标审核模型节点的记录耗时合计 51.5 秒。
- 内容仍有需人工复核之处：正文一处将作者的“很可能”概括为“才是实质”，比原文 L9 的不确定性更强；原文 L49-L55 的风险管理立场未纳入单篇深读总结。本轮不把行情同向当作人为砸盘的因果证明。

### Q07：作者画像

- Run `15953e453b9844c9a2641cf20a03fefc`。Trace 的 `evidence_audit.article_reads` 覆盖 18 篇不同 TT 文章、19 个正文片段；答案却称“本轮实际读取正文 8 篇”，并将实际读过的 2026-08 至 09 月文章列为“未读”。这是可用 Trace 直接证伪的取材范围陈述。
- 答案“已读样本内仅出现一次”第 7 项又明确写“在两篇均提及”；答案还把 2026-07-30 的观察窗口放进截至 2026-10-13 `not_due` 的清单。内容验收不通过。
- 本轮没有 ArticleCard，只有 1 个 research_note；有 5 次 `context_offload` 和 24 次 `context.open`。终稿未提交 `review_targets`，转入旧版 `model_pass_over_observed_evidence` 审核；后者经过 81 个原子/跨文审核模型节点后给出 `accept`，却没有发现上述范围、内部矛盾和时态错误。不能将此 `accept` 视为业务通过。

### Q14：两作者对比

- Run `777320fd0e514fb98fd05c602f43f991`。实际读取 TT 7 篇、培风客 4 篇，且有 skeptic 委派；来源覆盖和独立复核触发属实。
- 没有生成 ArticleCard，也未提交 `review_targets`，仍走旧版逐段审核。审核提出 11 项争议，最终保留完整研究稿并在开头列出 3 组争议，符合“不因争议删除答案”的交付边界。
- 但被质疑的核心归纳仍在正文中作为较明确的“分歧实质”出现，例如“TT 不再把加息降息当作短期核心变量”和“TT 将拐点锚定四季度”。审核意见指出原文存在加息条件情景、尚未发生的流动性条件和时点限定。内容和证据判为未通过，不能仅靠开头的争议块覆盖正文中的确定性措辞。

### Q22：官方资料交叉核查

- Run `4bec4f701671491b9bb75beba70b25fd`。读取三位作者共 6 篇相关正文，并打开美联储 FOMC 声明、会议页、SEP 页面；skeptic 也被委派。官方事实与作者观点分层呈现的基本路径存在。
- 0 张 ArticleCard。最终稿有 2 个 `review_targets`，但目标审核因结构化响应错误失败 3 次，未触发 `finance_review.normalize.v1`，最后只能以 `review_failed_full_draft` 发布。
- 答案把培风客原文“今天的点阵图，年内两次加息”裁定为与官方“年内再加一次”矛盾。原文并未明确“两次”是全年合计还是本次之后还要两次；“全年合计两次”与“本次已加一次、年内再加一次”可以一致。因此当前证据不足以发布确定性的“事实偏差/矛盾”裁定，至少应标记口径未明并说明两种解释。这是本轮最重要的错误裁定。
- 官方资料虽在 Trace 中有网址和原文，最终答案只写来源名称，没有直接给官方资料 URL/EvidenceRef，用户在答案里不易独立回查。

## 归因与下一轮顺序

**设计已明确、实现未达标（事实问题）**

1. 多篇阅读后没有逐篇 ArticleCard；因此无法稳定追踪“哪篇文章支持哪个观点”和实际抽样边界。
2. `review_targets` 缺失时回退到旧的逐段审核，造成大量模型调用，并可能给出掩盖范围/时态错误的 `accept`。这是与第 13.2、13.3 节并存的迁移路径，验收不应把它当作目标设计已落地。
3. 目标审核的模型适配层报“响应缺少 JSON 对象 output”时，`complete_structured` 的结构修复没有接管，导致 `review.normalize` 从未触发。应先修恢复链路并留可见 Trace。
4. 结果交付前没有可靠核对“已读文章集合 vs 答案声称的样本集合”；Q07 直接错误描述取材范围。

**下一轮需要设计权衡**

1. 简单元数据查询是否提供紧凑作者汇总输出，避免把 500 条文章候选搬进上下文。目标是减少无效上下文，不是减少必要的深读。
2. 作者画像如何从逐篇卡片收敛为代表性样本、如何披露“已读/已用于结论/未读”三个不同集合，以及何时停止取材。
3. 审核对象如何按语义而非答案行数选择；审核应检查样本范围、时间状态、分母口径和“全年合计 vs 剩余次数”等比较前提，而不是只核对原文片段。
4. 有争议时，是要求主 Agent 将争议整合进正文对应结论，还是允许单独的争议栏；当前只在前面加争议块容易留下正文的肯定句。

建议先解决前四项实现偏差，再用同一组 Query 复跑对照；上述设计取舍由用户决定后再修改主链路。不要以降低审核标准、缩短研究稿或简单减少模型调用次数作为“性能优化”。
