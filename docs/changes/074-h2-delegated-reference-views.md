# H2 委派来源身份与可用引用的最小分离

日期：2026-10-20。性质：修复冻结接口 7/8、026 与 062 的实现偏差，不批准 072 的其余研究方案。
用户已授权：已有设计的事实问题直接修；常规技术借鉴，复杂问题按 MVP 推进。

## 1. 具体缺陷

R17 的深度二已实际运行，但一级任务引用孙任务私有 Artifact，结果变为 partial。
`_consume_observations` 把结果 envelope.evidence_refs 当成父任务已可用的引用；
`_inherit_source_lineage` 又把这些 ID 放进 article.material_refs；状态增量合并还从旧账本重新吸收它们。
知道来源身份不代表获授原文，也不代表父任务已读取原文。现有 Repository 权限拒绝是正确的，不应放宽。

## 2. 最小修复与接口

保留 AgentAction/ResearchResult、权限与 ResultRef；不新增模型工具、数据库字段或金融分析流程。

- 子结果的 `result_ref` 与父任务自己持久化的全文 wrapper 是可用入口。原始 refs 仍在原结果、
  envelope 与 finance_sources 中用于溯源，不再因返回而成为父任务的引用或输入材料授权。
- Runtime 的紧凑 execution 增加 `delegated_source_refs`：按已观察的结果句柄记录来源 ID；
  `local_evidence_refs` 保存本任务真实工具观察产生的引用。两者都是恢复索引，不是模型自报授权。
- 现有 known_evidence_refs、article 的 material_ref(s)/result_ref(s) 与状态增量/终稿校验，
  排除仅从委派返回的来源 ID；明确给本任务的 input/material 授权、自己真实观察的引用、
  已直接取得的结果句柄不因同时出现在溯源中而失效。
- 不删除已有证据账本历史。旧的来源 ID 行标注 `reference_kind=source_provenance`，
  不再被状态增量当成可用引用；原 EvidenceRef 不静默改写成另一个 ID。
- 旧 Checkpoint 缺少新索引时，从已持久化的任务观察和 result.get 观察恢复一次。
  只读取已有观察记录，不读取原文章，不增加模型调用，不扩大权限，不修改历史数据库产物。
  后续按新观察增量更新；现有紧凑状态大小限制保持不变，不添加静默截断。
- 上下文用简短协议说明区分“子结果的来源身份”与“父任务可引用句柄”。不注入新整套 Skill。
  父任务引用子分析中的原有文本；若要引用原文摘录，仍须满足原来源访问/摘录契约。
- 原文读者、作者、日期、版本和已读范围按 062 原样逐级传递；引用子结果不伪装为父任务亲自读原文。
  未读全文的长结果保留渐进读取边界，不能仅有句柄就认可完整来源。
- 主/子 Agent 仍自己选择使用哪些分析。错误引用仍被剔除并披露 partial，不代模型猜引用或消除争议。

该修复只落实既有权限和交接语义。074 不引入 072 中的新强制逐结论结构、定向审核或外部查证规则。

## 3. 验证计划

1. 先复现新观察污染、旧 Checkpoint 恢复后污染、增量合并重新污染三类问题。
2. 实际 SQLite/FakeRedis/模拟 HTTP 模型执行深度 0/1/2，仅孙任务读原文；一级分别引用
   自己的 wrapper 和显式读取后的 ResultRef；Root 接收完整来源链，不出现权限扩大或重复原文读取。
3. 覆盖显式授予的相同来源仍可用、私有来源不被自动授予、失败任务不产生来源、未读尾页不伪装全文、
   恢复索引不读原文、不增加模型次数，以及真实状态/终稿不会因账本旧行重新接纳私有引用。
4. 受影响模块、完整 H2、默认金融和配置隔离回归；离线通过后再冻结新真实模型批次。
   保留 R17/R20 等旧结果，不以模拟 Redis 代替真实 Redis 或生产负载验证。

实际结果执行后补充；总目标保持 active，不能以本项修复代替完整基线与 Query 验收。
