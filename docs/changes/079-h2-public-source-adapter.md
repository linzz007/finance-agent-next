# H2 公开来源工具的最小接入

日期：2026-10-20。范围：修复 RC09 中公开检索与打开网页的既有业务接入遗漏。
依据：[017](017-harness-v2-finance-loop-integration.md)、接口 H2-C16，以及用户对常规技术修复/MVP 的授权。
先记录本文，再实现；不是 072 剩余审核、收尾、行情、Wiki 或持仓设计的批准。

## 1. 归因与复用

旧 1.0 已有 `WebResearch` 和严格 `web.search/web.open` 输入模型，但 H2 没有绑定。
这导致部分 Query 在预检就被阻断，不是模型不聪明或金融验收要求过高。
复用现有公网 URL/DNS/重定向限制、超时、体积和格式限制，不另写 HTTP 抓取器。
沿用 [073](073-h2-framework-informed-anchor-repair.md) 核对的 pi/DSH 执行前校验和显式错误结果机制；
它们不提供本项目的金融证据绑定，不能把来源可读称为结论已验证。

## 2. 最小执行与证据契约

1. `for_finance_corpus(public_sources=...)` 由可信入口显式注入适配器；默认不联网。
   只有适配器已绑定且当前 Task 权限快照允许时，模型才可调用相应工具。子/孙仍取父权限交集。
   原文的 input-material 文章范围不扩大；公网能力不允许读取本地文件或私网地址。
2. 使用原 `INPUTS`，描述和执行共享 Schema。每次执行建立独立的旧版 WebResearch/EvidenceLedger，
   不跨 Run/Task 共享可变搜索缓存；旧 evidence_id 不当作 H2 ArtifactRef。
3. 每动作保存真实工具结果，再按现有步骤 checkpoint/requeue。已提交观察在恢复时从 artifact 读取，
   不通过重新联网伪造恢复。未提交外部请求的崩溃窗口仍可能重新抓取，不承诺 HTTP exactly-once。
4. 搜索结果是导航线索，不是网页正文。成功打开并得到非空正文才产生 public_web_page 读取证据；
   不支持格式、无结果、超时和访问失败保留原因，不产生已读来源或外部核实成功。
   抓取错误不附带原异常字符串/凭证；取消、租约与存储错误仍按原边界传播。
5. H2 保存正文 artifact 和真实 URL、抓取时间、发布日期（可空）、原响应 hash、返回行范围及分页状态。
   抓取时间不是发表时间，不给网页编造文章作者或发布日期，不把公开网页塞入 `article_states`。
6. 研究子任务引用成功打开的网页时，沿用已有原文逐字摘录和锚点检查；搜索摘要和失败结果不能
   通过该来源检查。原正文仍在校验前保存，未通过时完整交付 partial，不丢弃分析。
7. 沿用 finance_sources section 回传公开来源溯源（kind、URL、hash、时间、范围、原 reader_task_id）。
   父任务得到自己可用的结果/材料句柄，不获得下层私有原文权限；两层传递不能丢失原读者。
   来源存在只证明可追溯，不认证模型因果推断，也不强迫 Agent 为每个问题联网。

## 3. 验收入口

运行器显式 `--public-sources` 才实例化生产适配器、增加对应权限并声明已绑定能力。
预检只解除 Q03/Q19/Q20/Q22 的相应公开来源阻塞；Q21 仍缺行情历史，Q23-25 仍缺私有上下文，
Q30 仍缺指定故障注入。未启用时保持原预检。可执行不等于联网可达或答案正确。
测试可显式注入 fixture 适配器，必须标为离线，不把 fixture 内容当真实联网结果。

## 4. 验证要求

- 未绑定、权限缺失、子任务权限受限时不发生外部请求；描述和执行参数一致。
- 原安全抓取器仍拒绝 file/私网/非法 URL；失败与搜索线索不被当正文。
- 临时 SQLite/FakeRedis/模拟模型完成打开网页、委派、两层来源回传和新 Service 恢复；
  已提交网页不重复获取，引用可追溯、原读者和时间保留，私有原文仍不可直接读取。
- 原文摘录失配、搜索摘要冒充正文时保留完整分析并披露 partial。
- H2 与默认金融离线回归、配置隔离、静态检查；默认 1.0、预算、模型和数据库 DDL 不变。
- 真实联网/模型另写新冻结协议和结果，不追加或重写 R22，不把单次交付称为商业稳定。
