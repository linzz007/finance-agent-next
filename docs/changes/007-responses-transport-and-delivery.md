# Responses 传输与终稿交付稳定性

日期：2026-10-17。设计：用户已确认；可选适配及分层验收已收口，真实金融交付仍未通过。

## 1. 目的与边界

变更 006 的 GPT Q04 在终稿首正文前连续断连；工具契约恢复不能修复这种故障。
本轮保留 Chat Completions，增加可配置的 Responses 文本适配；只有分层对照
结果支持时才讨论默认切换。Responses 不是原生 Function Calling：不发送
`tools`，继续校验现有公开 JSON action，不执行原生工具、DSML 或隐藏推理。

不改变主 Agent 的规划、选材、读法、委派、验证目标和收敛决定，不增加金融
审核强度、数据库、队列、前端、跨供应商自动降级或运行中的模型切换。
已有完整合法候选稿仍按现行交付规则保留；断流片段不冒充完整候选稿。

来源：[OpenAI 流式指南](https://developers.openai.com/api/docs/guides/streaming-responses)、
[流事件定义](https://developers.openai.com/api/reference/resources/responses/streaming-events)、
[中转站配置说明](https://doc.cctq.ai/guide/deepseek-harness.html)。前两者定义接口，
后者推荐 GPT 的 Responses 接入，但都不是本项目的稳定性证明。

## 2. 配置与请求

- 增加 `protocol=openai-responses`，命名配置 `gpt-responses`；沿用 gpt 的模型、
  地址和凭证变量。现有 gpt、deepseek 及无命名配置的默认值不变。
- 启动和测试仍用 `--model-profile`，进程内固定配置。显式选择 Responses 失败
  不静默回退 Chat Completions，也不跨模型拼接结果。
- 发送 `POST <base_url>/responses`，使用 `instructions`、带原有角色的文本
  `input`、`max_output_tokens`、`stream`、`store=false`。每次发送完整本次输入，
  不使用 `previous_response_id`、服务器会话或后台任务。没有 `tools`。
- Responses 不发送 DeepSeek 专有 `thinking` 参数；该不支持组合在请求前拒绝。
  不为迁移改变温度或研究 Prompt。Bearer 鉴权和既有请求头保持一致。
- 复用现有预算、请求账本、超时、退避和逻辑决定最多五次物理请求，不增加
  适配器内部的隐藏重试。连接/空闲读取及运行剩余时限继续约束每次请求。

## 3. 接收与完整性

```text
固定模型配置 -> 同一逻辑请求/预算 -> 发送完整输入
  -> JSON 响应 / 按 SSE 空行解析事件（支持分片 UTF-8、CRLF、注释）
  -> 等待完整终态，校验响应 ID、状态、公开文本及流式累积的一致性
  -> 标准化为现有 ModelResponse -> 原 JSON 动作、参数、证据和权限校验
  -> 执行工具 / 返回完整候选稿 -> 原金融验证与交付流程
```

| 实际结果 | 处置 |
| --- | --- |
| `completed` / SSE `response.completed` | 从终态 `output[].message.content[].output_text` 提取公开正文；忽略 reasoning；校验完整后才送原动作解析器 |
| 有文本 delta，但 EOF、断连、缺少终态、ID/文本不一致 | 本次缓冲不执行、不发布、不与重试拼接；暂时性传输故障按现有额度重试同一请求 |
| `incomplete` 且 `reason=max_output_tokens` | 保持截断状态，不执行；交给既有一次输出预算恢复，不能仅因 JSON 恰好闭合而放行 |
| `incomplete` 其他原因 / `failed` / 拒答、内容过滤 | 保留明确状态、原因；永久失败不做格式修复；限流/服务端临时错误按既有规则重试 |
| `completed` 但无公开文本 | 记 `empty_public_response`，走已有共享额度的协议纠正，不读取 reasoning/native 字段补答案 |
| 完整正文但 JSON 不合约 | 原变更 006 的有界纠正；不增加第二层修复循环 |

流式不要求 Chat Completions 专属的 `[DONE]`；Responses 的匹配终态事件才是
完成信号。非流式同样必须有可信终态；`queued/in_progress` 不当成功。
单事件 1 MiB、总响应 8 MiB；心跳不重置总时限。不承诺系统 DNS/原生阻塞
调用的硬实时取消，也不声称供应商恰好执行一次。

## 4. 可观测性与兼容

在既有 `transport_attempts` 增加 `api_style`、`response_complete`、
`completion_state`、`incomplete_reason`、`response_id`；保留 profile、请求/返回
模型、HTTP 状态、首个公开文本耗时、公开文本字符数、事件数和各次耗时。
`response_complete=true` 表示收到有效终态，不等于成功答案：截断/失败有终态
也必须单独记录。既有 `stream_complete` 仅表示 SSE 收到有效终态。
不持久化隐藏推理、鉴权信息或断流正文。成功率必须区分原始单次传输、恢复后
有效动作、研究完成及金融质量，不能把四者混算。

Chat Completions 仍需 `finish_reason=stop|length`；内容过滤、原生工具终态、
缺失/未知 finish reason 不作为正常完整回答。补齐其非流式完整性检查。
既有 action、EvidenceRef、ArticleCard/v2 和前端接口不变。
正式配置及传输契约见接口文档 6.3-6.5，不建立第二份金融行为定义。

## 5. 分层验收与停止

1. **离线协议**：JSON/SSE、中文/字节分片、多行事件、reasoning 忽略、usage、
   身份/正文不一致、空正文、拒答/过滤、截断、EOF、HTTP/流内错误、退避、
   次数与时限、大小上限、凭证脱敏及旧接口兼容。必须证明不完整工具不执行。
2. **离线整体**：金融/共享 Runtime 基线、路径预检，隔离临时数据、零真实凭证。
3. **真实传输对照**：同一模型与参数，Chat/Responses 交替；短文本、长输入、
   长输出、公开 JSON 工具动作、连续多轮，每种每条路径至少三次。探针只用
   合成信息，原始单次调用不隐藏重试，保存输入哈希、协议、结果和时延。
   多轮每次完整重发上下文，不使用远端会话。认证/余额/路由等永久错误或
   同路径连续两次传输失败停止该路径，报告未覆盖项，不无限付费循环。
4. **真实金融**：合成探针通过后，使用已有冻结快照和未改写的 Q04/Q14 分别
   检查研究/交付 Trace、答案和来源。受控预算、次数单列；不因模型未选新版
   Subagent 而宣称已覆盖它。探针不通过则先报告环境/协议阻塞，不硬跑业务。
5. **收口**：记录实现、离线、合成、业务四种状态及残余问题。默认配置保持，
   不用有限样本或一次完整回答宣布商用稳定性、语义质量或所有设计已通过。
