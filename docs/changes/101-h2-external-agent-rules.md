# 101 H2 角色与 Prompt 资产外置

日期：2026-10-22。状态：用户已确认规则与执行解耦，先设计后实现；代码及离线回归完成，现有网页进程尚待重启。

## 1. 范围

将 H2 金融主/子 Agent 指令、角色说明、来源规则、工具用途简介和补正指令移到仓库文件。保持执行器、公共动作/结果 Schema、权限、预算、租约、调度与错误收口语义不变。

这不是增加重试次数、自动换模型或新增金融语义门控。一次格式补正不是独立同分布抽样，也不构成成功率证明；补正上下文比首次增加 Schema/有界诊断，不能用两次各 70% 来计算可靠性。普通补正再失败仍报告故障，适用锚点分支仍冻结并保留正文。

## 2. 资产与执行分工

- `config/agents/finance.json`：三个角色的用途、指令引用、交接要求、共同输出契约及内部版本别名。采用标准 JSON，兼容 Python 3.10，不为 TOML 额外增加依赖。
- `prompts/finance/*.md`：主指令、子公共指令、角色方法、来源规则、调度/失败建议、两类补正指令。
- `prompts/finance/tool-descriptions.json`：工具与调度用途简介，参数 Schema 仍来自程序模型。
- 加载器只作严格文件/模板/角色/哈希校验和确定性装配，不解释代码、不改变实际工具权限，也不决定金融结论。

Root 使用简短角色目录，角色用途和子角色指令来自同源定义；详细参数仍由 tool.describe 按需读取，不向 Root 灌入全部子 Prompt。所有角色仍共用既有 Spawn 与 ResearchResult，不要求主 Agent 动态发明 Schema。

## 3. 快照与恢复

新金融 Run 在创建时加载规则包，保存各资产内容及 SHA-256，并形成总摘要。规则包存为独立不可变 Artifact，Root Brief 引用它。使用已有 Artifact/Brief 结构，不新增表或更改数据库 DDL。

每次执行从 Run 的 Root Brief 取同一规则包，供 Root、子/孙、补正及恢复使用；不用父/子模型提供的字段覆盖规则。规则不列入材料授权，不可作为证据或用于提升权限。正文输入只含所需指令与角色目录，不重复注入整包资产。

磁盘修改只影响新 Run，正在运行的 Run 不热更新。相同 run.create 重放沿用首次已冻结的规则，不因磁盘变化产生新任务。篡改、缺失或哈希不符的已声明快照必须报告故障，不悄悄回落到当前文件。

外置前的旧 Run 没有规则快照，无法凭空还原其历史每次输入。本次保存迁移前现有指令的固定兼容包，缺少快照的旧金融 Run 使用该包并标明兼容来源；不能宣称恢复了所有更早版本的原始 Prompt。新 Run 不允许因为规则文件损坏而走旧包。

## 4. 模板与边界

仅允许预先声明的占位符。动态值为可信角色名称/角色指令及既有预算策略说明，不把原始用户内容作为指令模板执行。正文中的 JSON 花括号保留原样。不支持 eval、任意文件引用、路径越界或配置指定新付费模型。

外置时以迁移前渲染内容哈希做等价检查。已确认的主角色目录属于明确新增输入；其余文案不借机重写金融分析要求。Schema 和实际工具执行仍由 Python 控制。

## 5. 失败观察示例

模型输出 article.read(arguments={id: A}) 后，参数校验失败，保存 `status=failed` 的动作观察，其 payload 包含 `ok=false`、`invalid_arguments`、`describe_name=article.read` 和有限字段错误路径。下一次决策的 action_observations 显示真实失败；tool.describe 可补充准确参数，然后模型用 article_id 重试。

未授权引用不能靠上述过程获得新权限。失败观察不进入已读来源/有效证据。原记录保留，后续正确调用产生单独成功观察。补正请求、传输重试和普通工具纠正的记账边界不合并。
