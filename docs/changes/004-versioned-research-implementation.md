## 1. 本轮应完整交付什么

建议本轮完成一条可实际使用的新版可选研究路径，而不是只增加 Schema 或只写一份 Prompt：

| 范围 | 本轮目标 |
| --- | --- |
| 任务和执行者 | 显式选择 analyst v2，绑定一次任务描述、授权材料与来源版本；旧 analyst v1 的调用和输出继续兼容 |
| 单篇阅读 | 短文深读全文优先；浅读保留范围；返回任务导向的连贯理解、重要证据联系及局限，不强制 claims 或固定章节 |
| 综合 | 主 Agent 可将完整理解交给同一版本的 analyst 综合，或自己分析；结果保留来源、日期、条件和未处理范围 |
| 中间产物与恢复 | 接通 v2 保存、完整读取、分页及失效检查；真实压力下才换出，授权恢复不能只返回“之前读过”而没有可用正文 |
| 证据、失败与 Trace | 接通证据导入、接收与处置记录；保存失败、模型失败和部分覆盖分别可见，有效内容不因普通审核失败全部消失 |
| 主 Agent 接入 | 通过短 System Prompt、能力 Skills 和显式工具描述暴露新路径；主 Agent 自主选择，不使用作者名或金融关键词安排固定流程 |
| 证明 | 旧版回归、新路径边界测试、实际模型链路及答案人工验收分别记录，不用结构通过冒充金融质量提升 |

不包含：新数据库表、队列/租约、递归 Subagent、跨运行记忆、新模型框架、多人注册、前端重做和原项目改造。当前委派仍可同步执行，不将本轮称作持久化任务平台。

任务、结果和存储字段只引用[正式接口第 8 节](../finance_agent_interface_contracts.md#8-versioned-research-integration-contract)，检查标准只引用[验收第 6-8 节](../finance_agent_eval_v1_acceptance.md#6-文章理解交接与全文优先的增量检查)，这里不复制第二套字段表。

## 2. 静态核对发现的实际约束

以下保留实现前的静态约束快照，不是修改后的现状、线上运行测量，也不推定当前环境采用所有默认值。当前实现见第 7 节：

| 位置 | 可见事实 | 本轮需要处理的影响 |
| --- | --- | --- |
| [旧角色注册](../../plugins/subagents/roles.json) | analyst v1 为 22 步、14 次模型决策、240 秒 | 不应把该时限直接当作新全文阅读能力的合理时限；旧版本保持兼容 |
| [金融主循环](../../src/policy_impact/harness/agent_runtime.py) | 当前自主研究路径使用 900 秒、120 次主循环模型决策、60,000 估算 token 的上下文换出阈值；另有 5 次委派和业务条件预留名额 | 新路径需要显式配置与真实预算记录，不能直接继承业务特例；这些数值不是模型质量或容量结论 |
| [Subagent runner](../../src/policy_impact/harness/subagents.py) | 子任务自己计算 deadline，调用模型前没有把该 deadline 作为完整重试预算逐层传递 | 单次流上限、子任务时间和父任务预留需要统一，否则子调用可能占尽父任务交付时间 |
| [模型网关](../../src/policy_impact/harness/model_gateway.py) | 同一尝试循环处理传输失败、JSON 问题和输出截断；部分非聊天 Schema 截断后要求不超过 900 个中文字符、数组两项 | 新契约不得进入这种强制缩减正文的分支；需要拆分恢复原因并防止多层重试倍增 |
| [AgentLoop](../../src/policy_impact/harness/agent_loop.py) | 另有一次动作结构反馈机会；候选已返回但越过 deadline 时，存在返回空 final_output 的分支 | 新路径需要保留合法候选和失败原因，而非把“超时”和“从未形成分析”混为一谈；不能因此跳过必要来源校验 |
| [文章读取](../../src/policy_impact/domains/finance/article_gateway.py) | 单次至多 100 行；重复范围可能只回证据 ID 和空正文 | 获取分页不应强迫模型逐页分析；明确需要恢复时必须取得合法历史原文或版本绑定快照，不能将空缓存回执当作模型看到正文 |
| [token 估算](../../src/policy_impact/harness/context_manifest.py) | 使用中英文混合启发式估算，不是当前服务的精确 tokenizer | Trace 需保留估算方法与误差余量；不能声称 60,000 是当前模型的舒适窗口 |

这些事实说明需要协调接口、Runner、网关和接收逻辑，不能仅把阅读要求加进 Prompt。通用模块的修改也须跑旧版回归；兼容旧协议不意味着将明显不适合 v2 的短输出规则继续套到新协议。

## 3. 输入容量与全文/分段分支

### 3.1 输入预算建议

模型配置明确区分：服务允许的总上下文、单次输入上限、单次输出上限、本次输出预留、估算安全余量和当前完整请求的大小。完整请求包括 System Prompt、Skills、任务、材料及历史、工具/结果 Schema 和协议包装，不只计算文章文本。

按当前服务定义，若总窗口同时包括输入和输出，可用输入取以下限制中更严格者：输入上限，以及总窗口扣除本次输出预留和安全余量后的空间。服务没有公布某项时，记录未知，不把模型名称当容量证明。配置值和来源必须进入 Trace；没有可靠容量信息时，先使用标明“暂定”的工程配置，并在真实业务验收前用合成材料做边界探测或取得服务方说明。探测只证明测试过的请求，不证明所有内容在该长度都能正确理解。

准确 tokenizer 可用且与实际服务匹配时优先使用；否则保留现有估算并加可配置余量。收到明确的上下文过大错误时，降低本次可用输入估算或切换分段，不反复发送同一个超限请求。不得在未记录的情况下截断任务、删除条件或把 deep 改成 skim。第 7.2 节已记录暂定工程数值；其容量及质量适配仍待实测，不让用户凭空选择“最舒适窗口”。

### 3.2 阅读与恢复流程建议

1. 主 Agent 确定任务、材料及深度；Runtime 验证授权、固定版本，并预检实际输入大小。
2. 已选深读且适配时，Runtime 将该文章的完整授权文本作为真实来源观测装配进子任务；分页获取可以合并为一次分析输入，证据和行号不合并成虚构来源。子 Agent 可直接完成，也可为具体缺口回读。
3. 浅读按显式范围或被授权的选段方式执行，不因短文适配就自动改成全文深读。
4. 恢复已读范围时，按权限取得对应版本的原文观测或快照；恢复属于原观测的再次可见，不算新的独立来源或新增研究覆盖。
5. 全文不适配时，推荐下表的“主 Agent 协调分段任务”。它是输入超限的工程分支，不是所有文章的固定金融分析方法。

| 超长文章候选 | 机制 | 取舍 |
| --- | --- | --- |
| 主 Agent 协调分段任务（已选择） | Runtime 返回真实超限原因、版本、可授权范围及预算信息；主 Agent 用现有 analyst v2 和范围任务安排分段阅读，再组织或委派文章级整合，授权必要原文回查。阶段结果沿用同一任务/结果契约，记录与原深读目标的关系，不需要子 Agent 递归派活 | 多个已完成结果可恢复、失败范围明确；主 Agent 多承担一次协调，可能增加调用。不会把分段任务的 skim 标签当成完整 deep，也不会以“分段都返回”自动认证最终理解完成 |
| 子 Agent 内部持久化分段工作状态（备选） | 一个长寿命子任务自行保存阶段理解、换出、恢复和整合，需要再定义子任务工作区写入/检查点接口及故障语义 | 父任务协调较少，但会扩大本轮权限、状态和恢复接口范围，不能仅凭已有只读工具循环就宣称具备 |

整合可以使用分段形成的连贯理解及必要工作视图，而非 claims-only；必须能回到各段原文，并保留缺失段落、条件和反向观点。子结果和上游输入范围共同参与覆盖追踪；未收到原文的整合调用不得声称自己再次通读全文。超长与超多材料均不能因预算不足而假装全量完成。

## 4. 运行与恢复预算建议

### 4.1 质量优先的初始运行配置（已确认方向与时限）

建议个人研究使用以下可配置初始上限，原因是用户更重视分析完整性、允许较慢，不是因为测出了模型的最佳参数：

| 项目 | 建议初始值 | 约束 |
| --- | --- | --- |
| 整轮研究时限 | 60 分钟 | 是上限，不是需要用满的目标；主 Agent 有充分证据可提前结束 |
| 主任务收尾预留 | 10 分钟 | 新取材/委派不能侵占该部分；用于综合、验证决定、必要修订与交付，不保证一定能完成全部审核 |
| 新 analyst 子任务时限 | 最多 20 分钟 | 实际取本身上限与父任务可分配剩余时间的更小者，不能延长父 deadline |
| 子任务收尾预留 | 最多 2 分钟 | 关闭新的取材循环，保留形成合法结果的机会；实际预留受剩余时间限制 |
| 新路径主循环决策次数 | 先沿用 120 次，预留 24 次 | 时间与调用次数任一先达到边界就收尾；不是 120 次真实 HTTP 请求的上限 |
| 全部模型请求 | 增加可配置的根运行请求总账 | 主/子任务、传输重试与结构修复均计入；数值在实现配置及隔离测试中明确，不把每层重试相乘后隐藏起来 |

所有模型调用、退避、源读取和子任务共享父任务剩余时间；请求前检查预算，重试/输出上限也取当前可用预算。不能只在模型完成之后才检查父 deadline。兼容网关的 idle 超时与单流时限继续区分，并随剩余预算收紧。

到了取材边界，主 Agent 仍决定怎样综合、如何解释缺口，Runtime 不替它决定金融结论。硬边界后不启动新的模型/取材操作；已经完整返回的合法候选仍可做有边界的本地来源校验、保存及有限交付，保留真实超时状态，不升级为成功子任务。仅有半截生成或不合法结果时不拼造完成稿。

### 4.2 有界恢复工程配置（本轮实现范围）

每个逻辑决策最多 5 次真实模型请求，共用总账与 deadline，而不是网关、AgentLoop、修复器各获得 5 次：

| 原因 | 建议处理 |
| --- | --- |
| 临时网络/服务错误 | 原始请求最多额外重试 2 次，使用有上限且受剩余预算约束的退避；有可用 Retry-After 时尊重它，超出预算则结束。断流不拼接片段，不执行半截工具动作 |
| 完整响应但结构不合规 | 给同一模型 1 次精确 Schema/字段错误反馈；仍不合规且有完整正文时，最多 1 次受限结构整理。只能重排现有内容，不能新增事实、EvidenceRef、研究步骤或升级覆盖 |
| 输出被截断 | 不视作完整结果，也不把片段作为独立分析。预算和服务上限允许时可做 1 次有明确变化的重生成，例如提高已许可输出额度或改为分段任务；计入同一 5 次上限。没有可行变化就返回限制，不反复同参数生成，也不下达“正文必须 900 字、数组两项” |
| 鉴权、未支持协议、不可纠正配置 | 不盲重试；记录可诊断错误，保留已有有效研究内容 |
| 越权、伪造/过期引用 | 不通过格式修复授予权限或替换来源；将具体错误反馈任务执行者，必要时交回主 Agent 处置 |
| 语义有争议或审核不全 | 不当作 JSON 修复问题；主 Agent 保留作者观点、反驳依据与局限，按现行验证/交付设计处理 |

结构整理只处理已完整收到、可以保留的公开结果，不解析隐藏思考或拼接断流文本；无法证明保真时维持失败，不以更漂亮的 JSON 冒充恢复。失败内容作为诊断保存，不能进入成功研究产物。已有合法结果另行保留，普通核验不足不一律阻止交付。

工程边界补充：外部取材在请求、重试和读取前检查父任务的可取材时间，现有采集线程继承该上下文；不更改来源白名单、DNS/重定向校验。系统 DNS 解析及第三方原生调用仍不能被 Python 同步超时强制中止，应记录为剩余限制，不能宣称具有硬取消能力。模型重试记录每次传输结果和实际退避，合法 Retry-After 超出剩余预算时不再发送。超时后保留的主任务完整候选只做本地引用/来源存在性检查，不再启动模型审核；校验失败保留已有合法研究而不发布伪造引用，校验通过也只能以未完成终审的有限结果交付，保留 timeout 状态。

现有重复恢复检查点也接受本轮新产生、通过验证且提交成功的 v2 理解/综合/工作视图作为进展，包含主 Agent 保存和子任务接收两种入口。不强迫新版为了恢复上下文先生成旧版 research_note。失败写入、无合法正文、只读已有记录或重复提交同一 ID 不释放检查点；原先的带依据笔记、实际计划进展与有限交付路径继续兼容。

## 5. 实现与证明的顺序

以下是开发和测试顺序，不是金融 Agent 必须执行的分析链：

1. 将正式契约映射为严格 Schema，补旧版/新版路由和预算配置，使用隔离材料验证权限、版本、恢复及超限分支。
2. 接通全文输入、按需工具循环、研究结果接收、v2 存储与 Trace；再接通综合、工作视图恢复和主 Agent 的可选插件入口。中间提交不作为最终验收完成。
3. 跑现有金融与共享 Runtime 离线回归，以及[验收第 8 节](../finance_agent_eval_v1_acceptance.md#8-版本化接口与运行内存储的增量检查)的新增故障夹具。特别检查嵌套重试总数、父子 deadline、恢复空正文、有效候选超时保留和旧协议兼容。
4. 模型配置容量不明时先使用合成短文核对完整响应、结构、输入/输出限制及预算收紧。须单独记录实际配置和请求数，不使用个人持仓或真实文章探测模型容量。
5. 在用户确认的固定文章副本上，建议先用 Q04（单篇深读）、Q08（作者概括）、Q14（多作者比较）做业务验收；题目原文不变。建议每题在同一模型/配置/快照下重复 3 次，先看可重复的链路与答案，再扩展到原 30 题，不把 9 次小样本等同稳定性保证。
6. 对照原文人工检查重要观点遗漏、条件/日期/作者混淆、推理解释、独立证据、取舍及最终表达。记录每次请求总数、真实耗时、恢复原因、覆盖和交付状态，不新增自动语义评分。实际未委派的 Query 不因缺少 Subagent 判失败；整套仍须有实际委派阅读/综合与恢复样本，未触发的能力明确列为未验收。

本轮不预先宣称一次实现后业务全部通过，也不建立无限修改/验收循环。验收发现已确认设计内的实现缺陷，修复后做针对性回归；发现未定义的金融判断或新架构取舍，记录问题交由用户决定，不为测试通过改设计。

## 6. 需要确认与后续边界

用户已确认本轮完整接通第 1 节的新路径、第 4.1 节质量优先的 60/20 分钟初始上限，以及第 3.2 节主 Agent 协调超限分段。输入容量和根运行请求总量等工程数值需在实现配置中明确、测量并记录，不能隐式沿用或宣传为最佳参数。

真实模型调用、固定语料副本及重复验收组合在执行前明确；本记录不授权后台长期循环。更广生命周期、跨运行状态和并发调度继续留在后续设计，不因某个文件保存成功宣称完成。先完成离线实现与故障回归，再区分实际模型链路验收与金融内容质量验收。

## 7. 实现映射与验证记录

### 7.1 已接通的调用关系

```text
主 Agent：识别问题 -> research.plan -> 自主选材料、深度和是否委派
  -> 显式 analyst@2.0.0 + research_task
  -> Runtime 解析已知材料、绑定版本/权限、装配全文或授权浅读范围
     -> 适配：analyst 看到真实输入，按需回读，返回连贯研究结果
     -> 超限：结构化返回容量、材料版本和行数，主 Agent 协调范围任务/整合
  -> 验证来源与实际输入 -> 原子保存 v2 + 完整内联结果/失败回执
  -> 主 Agent 自行或委派综合/工作视图，按需恢复原文和完整理解
  -> research.disposition：采用、限定、排除或跟进
  -> 既有覆盖、验证 checkpoint、必要终稿审核和有局限的交付
```

这张图是能力衔接，不要求每题经过每个节点。主 Agent 可直接分析并用同一 v2 保存契约，不必启动 Subagent。旧角色、工具和 v1 产物继续兼容，旧逐段 claims 分析不冒充新版全文阅读。

| 职责 | 当前实现 |

### 8.1 验收发现的记录缺陷与修复边界

以下两处属于既有契约的实现缺陷，修复只补记录，不更改金融研究行为。验收进程继续使用启动时已加载的修复前模块，未热加载修改；其源码与设计已按启动时哈希另存到忽略目录的 `provenance/code/`。新代码另做离线回归，修复前后的样本不能混算。

- 第 4.2 节要求失败内容作为诊断保留，但研究模型网关在完整响应的 JSON/Schema 校验失败后只留下错误文字，无法回查造成 `Extra data` 的实际公开输出。补充 `failed_public_responses`，记录尝试号、响应 ID、Schema、停止原因、脱敏公开文本及是否截短。每次最多保留 65,536 字符，并记录原长度；只保存完整、未被输出上限截断的响应，断流片段和协议中的隐藏推理字段不保存。该记录仅用于诊断，不进入成功动作、证据或研究产物，也不增加请求、解析容错或修复轮数。恢复成功和最终失败都保留此前的结构失败诊断，AgentLoop 继续传到 Trace。

3. 相同正文、问题、目标、个人上下文和实际依据可复用已验证的目标审核结果；任一输入变化必须失效。单目标成功结果可跨其他目标失败保留，传输/结构失败不缓存为成功。缓存返回独立副本，不能因调用方修改导致下轮结果污染。
4. 已完成目标与失败目标分开保留。传输中断不进入格式整理，也不抹去前面成功的检查；已有根预算、逻辑决策与重试边界不扩大。所有目标均未产生有效检查时如实记录 failed，而不是部分成功或 verified。显式空目标的 `not_requested` 不认证已验证，仍可交付并区分选择范围审核完成与语义未另行审核。完整安全研究稿与限制继续按既有交付规则保留。

6. 终稿审核的正文来源判断使用合并后的 EvidenceLedger，包含合法子任务取得的正文与行情/个人事实依据；不能因为主 Agent 没有亲自 article.read 就跳过审核。纯 `article_catalog` 元数据不因此升级为需要金融语义深审。父子已观测证据仍须通过既有身份与引用校验。
