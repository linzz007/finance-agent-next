# H2 有界动作 JSON 解析与模型尾部污染隔离

日期：2026-10-21。类型：已确认的通用协议故障修复，MVP。范围：H2 文本动作传输层；不改变金融研究语义、工具权限、预算、EvidenceRef 或模型选择。

## 1. 根因

R24b 的子任务出现了可复现的 `contract_error`。失败响应中有几类共同模式：

- 首个合法动作 JSON 后面拼接了模型自造的 `<system>` 工具观察和第二个 JSON；
- XML/DSML 风格的标签包住了动作 JSON；
- 模型输出自然语言前缀或没有任何可解析动作。

原解析器要求整段文本都满足 `json.loads`，因此第一类会被 `Extra data` 拒绝。第三类仍然应该拒绝。模型追加的工具观察不能被当成 Runtime 观察，也不能回灌给下一次模型调用。

## 2. MVP 协议

1. 仅对 `agent_action.v1` 使用有界提取。只有当单层 Markdown JSON 围栏内部恰好是一个完整 JSON 对象时才去除围栏；围栏内部含第二个对象、伪造 transcript 或其他非空内容时，整个外层格式仍拒绝。去除围栏后再扫描第一个完整 JSON 对象。
2. 第一个对象必须完整解析为 JSON 对象，随后仍执行原有 AgentAction Schema、工具参数、权限和金融结果校验。解析成功不等于动作合法。
3. 如果对象后面还有非空文本，只执行首个对象；尾部不进入观察、EvidenceRef、state update 或提示词。原始模型输出仍保存在审计 artifact 中，公开元数据只记录策略、前缀类型和尾部长度。
4. 只额外允许由 XML-like 标签组成的有限前缀，例如 `<tool_call>...</tool_call>`。自然语言前缀、多个外层围栏、数组、半截对象和任意 DSML 参数仍拒绝。既有的严格 DSML 文本工具兼容解析保持独立入口，不被本 JSON 提取器接管，也不扩大其可接受范围。
5. 如果首个 JSON 对象本身不符合 AgentAction，不能跳过它去执行后面的第二个对象。这样避免“第二个动作覆盖第一个动作”的安全问题。
6. 解析失败仍走现有分类诊断和一次结构补正；不增加模型调用、不切换模型、不追加预算。解析成功但业务/证据校验失败仍走原有校验与补正边界。

## 3. 参考机制与取舍

该策略借鉴成熟 Agent 实现中的边界原则：终态动作与流式预览分离，工具执行前做 Schema 校验，非法参数保留为失败而不是伪造成功。这里没有引入供应商原生 Function Calling，也没有复制某个框架的宽松“从任意文本找 JSON”逻辑；金融动作只接受一个可验证对象，兼容范围保持最小。

## 4. 验收

- OpenAI-compatible 与 Responses、流式与非流式均能执行“合法首对象 + 尾部伪造 transcript”；
- XML-like 标签包裹一个合法对象可解析；
- 自然语言前缀、首对象非法但后面有合法对象、半截 JSON 仍失败；
- 原始输出、实际动作、解析元数据与调用记账可追溯；尾部不会出现在工具观察或研究证据中；
- 围栏内多对象和围栏内伪造尾部保持失败；解析失败时已做的控制字符规范化数量仍进入有界失败元数据，修订诊断的错误偏移仍指向原始 artifact；
- H2、默认金融、配置隔离、静态检查回归不回退。

本变更只解决协议稳定性。它不能证明子 Agent 的研究结论正确，也不能解决条件性观点被过度归纳、外部证据不足或真实 Redis/并发尚未验收的问题。
