# JSON 动作契约与有界恢复

日期：2026-10-17。状态：本轮已按确认方向实现，离线回归通过；有限真实复验结束，业务未全部通过。没有切换默认模型协议。

## 1. 边界与来源

保留公开 JSON action 协议，不引入供应商原生 Function Calling、SDK 或 Agent
框架。主 Agent 仍自主决定读什么、读多深、何时委派、验证什么和何时收敛。
不调整数据库、队列、前端、原项目或金融审核的语义标准。

工具契约与错误恢复参考 [Anthropic 工具工程](https://www.anthropic.com/engineering/writing-tools-for-agents)
和 [BFCL 多轮评测](https://gorilla.cs.berkeley.edu/blogs/13_bfcl_v3_multi_turn.html)。
它们支持明确接口、可操作错误和多轮状态验收，不证明本项目具有某个成功率。
[中转站文档](https://doc.cctq.ai/guide/deepseek-harness.html)推荐 GPT 使用
Responses；文本传输接口和原生工具调用是两个不同选择。本轮单独核实文本
接口，不据此推断现有断连原因，也不未经验证切换默认模型协议。

## 2. 从规划到执行

1. 注入总体目标、公开动作契约、允许工具及其参数 Schema；同一工具目录只
   注入一次。具体业务说明仍放在插件/Skill，不增加问题类型专用流程。
2. 主 Agent 创建计划；现有规划门控与有界补救保留。
3. 模型返回一个完整 JSON action。先验证动作，再验证所选工具的参数类型、
   必填项、枚举与嵌套结构；通过后仍须执行原有权限、ID、范围和账本检查。
4. 参数 Schema 从同一组 Python 类型契约生成，供模型和执行端使用；JSON
   插件保留工具用途与字段说明，不再独立维护另一套类型定义。
5. 校验失败不执行工具。反馈字段位置、错误类型和纠正提示；由原模型选择
   下一动作。不猜测作者、日期、ID，不把 DSML/XML 文本直接当工具执行。

Schema 约束格式而非金融判断。跨字段业务条件、可访问的实际资源及证据
存在性仍由领域组件校验。旧版 ArticleCard/v2 研究产物兼容，不强制使用。

终稿审核目标也须事前提供既有 `FinanceReviewTarget` 类型生成的 JSON Schema，
放在主 Agent 可见上下文的 `review_target_json_schema`。此前 Prompt 只列字段名，
未说明 external_check_needed/importance 的合法枚举，真实 Q14 因此出现目标
形状错误。补齐类型信息不新增目标、不固定审核范围，也不把正文套进统一模板；
原有目标补充、失败后保留完整稿的分支不变。运行前可见性须有回归证明。

## 3. 恢复与错误分类

每个逻辑决定仍共享最多 5 次物理请求和父任务时间/请求预算，所有补救都计入。

- 传输失败：仅对暂时性网络/限流/服务端错误重试，最多 2 次，遵守退避和
  Retry-After；认证等永久错误不重试。不同尝试不拼接流式正文。
- 输出截断：不执行不完整动作；仅在允许提高输出预算时重试一次。
- 格式失败：原模型先收到具体错误、动作模板和脱敏的失败公开响应，允许
  最多 2 次纠正；这是协议反馈，不要求展示隐藏推理。
- 响应正常结束但公开正文为空：适配器显式标记 `empty_public_response`，与
  断连、截断和内容过滤分开。最多共享上述 2 次协议纠正，不把隐藏 reasoning
  或原生工具字段补成正文/工具动作，不叠加新的重试额度。
- 已有完整分析的终稿字段不合约：保留现有有界结构修复，正文、有效字段和
  证据标识不得改变。失败也保留可用正文，不能声称审核已完成。
- 本地上下文、时间或请求预算不足：不伪装成模型格式错误或网络断连，不
  无效重试；Trace 记录明确 failure_kind 和实际物理请求数。

模型适配器错误继承 RuntimeError，分类时必须先识别模型错误，再识别真实
请求预算错误；不能因为继承关系把远端断连记为预算耗尽。纠正正常结束的空
响应时，Trace 保留响应 ID、完成状态及空正文诊断；不伪造一条断连事件。

解析器不执行失败公开响应。失败公开响应仅用于协议纠正/诊断，脱敏记录，
最多保留 65,536 字符并显式标记是否截断；反馈放不下时保留 Trace 诊断而不
重复塞入上下文。不持久化隐藏 reasoning。继续恢复仍须经过同一动作及工具校验。

## 4. 上下文与恢复

先卸载较旧工具观察；如仍超限，再卸载近期较大的观察。最近四条不再是
不可突破的保护区。按预算大小处理，不让 Runtime 选择哪些金融句子更重要。
指令、原始问题、计划、完整证据原件不因卸载而丢失。

卸载保存原始对象、工具名和 checksum，模型收到运行内 context_id。小观察
仍可原样恢复；大观察使用 context.open 的字符分页视图，包含原始校验和、
完整长度、当前范围和 next_offset。分页是原始 JSON 的连续片段，不是模型
摘要，也不是新的 EvidenceRef。完整记录仍可从文件验证，跨运行/路径越界
及校验和不符仍拒绝。恢复循环的既有进度检查保留。

如不可卸载的基础指令本身超限，明确报 context_budget_exceeded；不静默
截断用户目标或权限规则。阈值是工程配置，不宣称模型的最佳上下文容量。

## 5. 交付与验收

有安全正文/资料已实际交付即 delivery_status=done；另用 stop_reason、
delivery_mode、verification_status 和 semantic_review 表示研究是否完成。
资料回退不是完整研究成功；审核尚未运行不能写成“审核不通过”。不降低金融
事实与证据门控，不因普通语义审核不完整删除已有安全的完整分析。
没有研究稿、只有材料和状态说明的回退标记 `delivery_mode=source_only`；
已有完整/部分研究正文但终稿或审核未完成可标记 qualified。未执行终稿审核
时，审核维度记为 failed（未完成），不是结论被反驳。错误提示不得写成
“未通过审核”，也不能把资料回退伪装成已形成带限制的完整分析。

离线检查覆盖动作/工具 Schema 一致性、嵌套参数、拒绝越权及虚构 ID、
格式纠正次数、DSML 不执行、传输/格式/预算分类、完整正文保护、大结果及
分页 checksum、交付状态。之后跑金融共享 Runtime 回归。

真实复验沿用已冻结数据及原始 Query，GPT 与 DeepSeek 分开记录，观察物理
请求、恢复、实际取材、最终分析和审核状态；有限次数不能证明商用成功率。
结果与剩余问题在本文件记录汇总，完整 Trace/文章/回答保存在忽略的 data。

## 6. 实施结果

已接通统一工具参数类型、嵌套 Schema、一次目录注入、两次格式纠正、
分类失败、近期大结果卸载、连续分页、完整候选保留与独立交付状态。
第一次完整离线回归 1318 项通过、30 项跳过；之后补充连续分页专项回归。
最终完整金融/共享 Runtime 回归为 1331 项通过、30 项跳过（48 个模块，
105.20 秒，真实模型调用 0）；核心故障专项 262 项通过，最后补齐审核目标
Schema 后的相关专项 103 项通过。这些专项互有重叠，不相加为独立样本数。
路径与配置预检 10 项通过，888 篇文章可索引。继承的 Starlette 弃用警告 1 项，
不属于此次协议恢复缺陷。以上数字不是全量旧产品或真实金融质量的通过声明。
首次真实复验已结束，不能以离线通过认定业务或商业化通过：GPT Q14 交付
3196 字完整比较稿，审核覆盖 partial；GPT Q04 终稿请求连续三次在约 61 秒
断连，只交付资料。DeepSeek Q04 读文和工具纠正成功后收到正常结束的空正文；
Q14 读到两位作者的 9 篇文章，但研究时限内未完成综合。以上失败不覆盖、不
改记为通过；空响应、失败分类和资料回退状态已完成回归及一次有限补测。
补充复测只重跑原始 Q04，使用同一冻结资料和 DeepSeek，不新增问题特判、
不切换默认接口、不提高预算。263.43 秒、42 次研究阶段物理请求后仍只交付
1176 字资料：最后一个逻辑决定连续三次返回 DSML，有界纠正耗尽；当时仍余
约 339 秒。现在分类为 format、交付为 source_only、审核为 failed，均与实际
状态一致。没有触发空正文分支，其恢复仍以故障注入证明，不能冒称在线已验证。
本次补测在最后补齐审核目标 Schema 之前运行，后者另以离线可见性回归验证；
不因该 Schema 修正重新启动付费全链路循环。

实现位置：统一输入契约 `domains/finance/tool_contracts.py`、插件装配
`runtime/plugin_config.py`、执行校验 `domains/finance/research_gateway.py`、
预算与恢复 `harness/model_gateway.py` / `openai_model_gateway.py`、上下文
`harness/context_offload.py` / `agent_loop.py`、目标 Schema 与交付
`harness/agent_runtime.py` / `domains/finance/answer_delivery.py`。相应插件
工具和 Skills 同步描述分页，不另建一套金融分析 Prompt。

本轮停止继续付费循环。剩余为 GPT 首正文前远端断连、DeepSeek 持续偏离 JSON
协议、审核输出结构/partial 收敛，以及新版 v2 Subagent 未触发真实样本。
完整私有报告为 `data/acceptance/006-tool-recovery-report.md`，批次分别为
`gpt006-01`、`ds006-01` 和 `ds006-02`；不把材料回退、一次完整稿或离线
回归说成全部金融设计已验收或商业化已通过。

本轮真实复验使用冻结文章、原始 Query 和独立数据库。为避免无限付费迭代，
测试使用 600 秒研究阶段、120 秒收尾、300 秒子任务/60 秒收尾、120 次根请求
的诊断上限；生产默认 60/20 分钟等配置不修改。测试限制将随结果一起披露。
准备、标题/意图识别及导出不全在研究阶段计时内，进程总耗时可能超过 600 秒；
该值不是 HTTP 请求或整个进程的硬时限，本轮不扩展生命周期预算设计。

Responses 调研：已阅读 [OpenAI 文本生成文档](https://developers.openai.com/api/docs/guides/text)，
其 input/instructions 可以只生成文本，无须提供 tools。中转站教程不是本项目
稳定性证明。当前配置仍使用原 Chat Completions 文本接口，后续协议迁移需
单独实现并验收 SSE 完成事件、截断、重试、内容过滤及兼容性，不能只改 URL。
独立的无工具、非流式 Responses 短文本探测：默认 urllib 请求头返回 403；
采用本项目相同 Content-Type / Accept / User-Agent 后，3.24 秒返回 completed
及 READY。只证明短文本接口可访问，不证明长上下文、SSE 或多轮研究稳定。
