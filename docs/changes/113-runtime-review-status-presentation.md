# Runtime 核验状态与分析快照分离

日期：2026-10-29。状态：用户已批准并实现；相关回归、真实归档只读复核与浏览器验收完成。

## 行为

沿用 111/112 的完整结果哈希、版本绑定、五轮上限和预算。新增只读展示合同
`finance.h2.review_status.v1`，由 Runtime 根据已持久化的 Analyst result.review 生成，
位于被核验的 result/review_targets 之外。模型不填写、不覆盖当前状态说明。

1. 明确区分当前核验结论与分析快照。状态包括实际 status、verdict、scope、轮数、草稿版本和报告引用；
   passed 文案必须有相应通过判定和绑定信息。旧版只有 reviewed 的结果仍标明未记录 passed 判定。
2. 父 Agent 完整读取子结果后，从相同的已验证结果中取得独立 review_statuses 上下文。
   分页不完整不得登记；该字段不授予证据权限，也不替代全文阅读。
3. 工作台实时/历史报告与任务树读取同一投影。报告顶部和 Markdown 导出列出各 Analyst 核验结论，
   不把子任务核验通过扩大为整份 Root 报告或外部事实已验证。资料阅读视图标明正文与限制是快照，
   当前状态单独显示；原始 JSON 保持原样。刷新仅重新投影，不调用模型。
4. 已保存结果不修改。历史通过稿含旧流程文字时，保留原文并展示时点说明；不得静默清洗正文、
   limitations 或 warnings。合法的“外部宏观事实未核实”限制继续保留。
5. Analyst Prompt 要求送审正文只写研究与持久限制；Verifier 发现临时流程状态时提出修改要求并复审。
   Root 使用 Runtime 当前状态，不将草稿中的“待核验”当作当前结论。Prompt 改动随新 Run 冻结，旧 Run 不换规则。
   合并 Analyst 中重复的模式、轮数、等待、意见处理和精确版本规则，控制固定指令开销；不扩大上下文上限或改变门控语义。

## 取舍与验证

本改动保证展示状态来自结构化记录，不保证模型所有自由文字永无过期描述。网页与导出保留快照说明。
状态收集只读取已接受结果与校验过的 Artifact，不从模型的最终总结反推通过。
工作台与资料阅读还必须核对数据库中的 Analyst 角色和已接受最终结果引用；普通正文或原始模型输出即使含同名 JSON，也不生成核验通过状态。
无核验记录显示明确空状态；损坏记录不得显示 passed。实时与归档不得跨 Run 读取，也不添加 Agent 阅读事件。

先运行离线反例与门控回归：旧文字保留、当前 passed 单独生成、修改结果仍需复审、off/partial/旧版诚实展示；
再验证父上下文完整读取、历史/实时 API、页面与导出的同源状态、分页及刷新无额外调用。
本轮不启动付费模型复验，使用已有真实 Trace 做只读验证。
