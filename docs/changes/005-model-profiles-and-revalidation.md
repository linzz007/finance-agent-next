## 1. 范围

在现有 OpenAI-compatible 网关上接入两份命名配置，不引入 SDK、自动故障切换、数据库、队列、前端或新的金融分析流程。主 Agent、子任务、结构恢复和终稿审核沿用同一次运行选定的模型及原有预算。GPT 与 DeepSeek 的独立复验分别记录，不拼成同一模型的成功率。

用户提供的 API 配置已经核对：GPT 当前服务的模型目录包含 `gpt-6.1-sol`；DeepSeek 官方接口的鉴权和模型目录请求成功，包含 `deepseek-flash`。目录检查不证明实际研究或生成能力。

## 2. 配置与选择流程

1. 启动器先加载现有本地环境，再应用明确传入的 `--model-profile gpt|deepseek`。不传参数时保留既有环境配置；也允许使用 `AGENT_WORKBENCH_MODEL_PROFILE` 选择命名配置。
2. 公共注册表为 `config/model_profiles.json`，只保存名称、实际模型 ID、协议、地址、凭证环境变量名、流式与可选思考参数，不保存密钥。严格校验未知字段、布尔值、思考力度及 URL；不存在的配置失败，不静默回退。
3. 命名配置对模型 ID、地址、协议和凭证路由拥有完整选择权，不与旧 `ANTHROPIC_*` 地址或凭证混配。DeepSeek 缺凭证时即为不可用，不能把 GPT 密钥发往 DeepSeek。旧环境用法仍保持兼容。
4. GPT 使用现有 `ANTHROPIC_AUTH_TOKEN`；DeepSeek 使用单独的 `DEEPSEEK_API_KEY`，均只在 Git 忽略的 `.env.local`/进程环境中保存。不修改默认模型或改写配置文件来执行测试。
5. 启动参数在进程启动时固定选择，不提供运行中修改入口。测试脚本支持同一参数，并禁止与裸 `--model` 同时传入，避免只换模型名却保留错误地址。更换供应方后建立新批次和新会话。

超时、尝试次数、研究时限、输入/输出预算仍沿用已确认配置。这里不宣称某个窗口或模型稳定性已经最佳。

## 3. DeepSeek 协议适配

按用户给出的请求及[官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode)：`deepseek-flash` 配置显式启用 `thinking`、`reasoning_effort=high` 和现有 SSE。思考模式不发送无效的温度参数。GPT 不发送 DeepSeek 专有参数，保留既有行为。

本项目用公开 JSON 动作信封，不发送供应方原生 `tools`。因此不需要将 `reasoning_content` 回传到下一次模型请求。推理增量既不作为答案/工具动作，也不写入 Trace、证据或产物；仅消费公开 `content`，沿用明确完成标记、截断拒绝、重试与结构恢复边界。官方说明是协议依据，不证明本系统已通过真实研究。

公开模型状态/Trace 区分配置名称、请求模型、实际返回模型、流式和思考参数，不含密钥。未指定思考参数的 OpenAI-compatible 配置以 null/供应方默认表示，不谎称已显式关闭；Anthropic 旧路径维持显式关闭。思考力度是运行配置差异，不用两种模型的时延或少量答案给出能力排名。

## 6. 验收宿主路径缺陷的修复约定

真实复验发现 Windows 验收目录过深：原子写入的目标路径达到 260 字符，而当前宿主未启用长路径，临时文件已创建但替换失败，造成已付费运行无答案。这不属于金融策略或模型选择；不修改系统注册表，不改日常工作区的存储布局。

脚本在加载凭证、建立批次、合成探测或研究调用之前，检查请求题目/次数对应的主运行生成路径：32 字符运行 ID、现有 context observation 和最长 v2 research artifact 文件名。Windows 采用保守的 260 UTF-16 码元路径边界，达到边界即要求使用较短批次目录；不因此宣称检查了所有第三方/子任务路径。Linux/macOS 不套用 Windows 上限。回归验证短路径通过、精确边界拒绝及拒绝前没有环境加载/目录创建/模型调用。失败原批次保留，新短目录结果单列。

预检已实现。模型配置/验收脚本定向回归 49 项通过；最终完整金融/共享 Runtime 回归 47 模块、1299 通过、30 跳过、1 条既有警告，101.66 秒。此前第 5 节的 1295 是加此预检前的结果，不累计。分离基线与编译再次通过，未再调用真实模型。
