# 102 H2 动作格式最多五次补正

日期：2026-10-24。状态：已实现并完成离线验证；真实模型复验未执行。

## 范围与计数

- 适用于 H2 Root、子和孙 Agent 的动作 JSON / 返回结构校验，以及既有冻结正文的证据锚点补正。
- 首次生成不计入补正次数；失败后最多补正五次，成功立即返回，不强行用满。
- 每次仍经过完整解析、Schema 和后续权限/证据校验；次数增加不代表放宽验收。
- 工具参数/执行错误继续作为真实观察进入下一步决策，不在此处盲目重放工具。
- 额度、权限、预算、取消、超时和模型服务错误不进入格式补正循环。
- 同一个决策的补正请求遇到传输错误，仍只额外允许一次相同请求重发，所有补正共享该名额。
  因而一次决策最多首次生成 1 + 格式补正 5 + 传输重发 1 = 7 次物理请求。
  每次均独立记账并检查原模型、预算、租约和截止时间；不自动换模型，不扩大总预算。

## 上下文与审计

每次补正输入为：原始 system/任务状态消息 + 一条当前补正反馈。
反馈包含专用补正指令、动作 Schema（子结果附内层 Schema）、最新失败的阶段、
安全字段错误或有界掩码语法定位，以及 correction_attempt / correction_limit /
corrections_remaining_after_this。每次依据最新失败更新，不叠加历次失败正文或整串补正消息。
原任务、真实观察和源材料保持原样；完整被拒输出只在审计保留。

锚点专用分支仍冻结原正文和来源，只允许修改原来无效的定位文本；五次都不合法时，
沿用既有部分交付：保留正文、删除无效绑定、显式警告，不能伪装全部证据通过。
普通动作五次都不合法则以 contract_error 结束；保留全部原始调用、每次诊断及最终失败摘要，
禁止通过新的 Attempt 隐式重置已耗尽决策。非格式故障按原原因结束，而非冒充格式错误。

## 规则身份与兼容

在 config/agents/finance.json 增加 action_repair_limit=5，代码只接受 1..5 的整数。
新 Run 将该值和补正指令一起冻结。旧快照没有该字段时解释为 1；恢复旧 Run 不读取当前配置。
既有 pre-101 兼容包及历史验收报告保持不变。无需 DDL、Redis 消息或前端变化。

## 验证

离线模拟首次成功、第五次补正成功、五次耗尽、最新错误更新且上下文不累积、
全决策只重发一次、预算/权限中断、旧快照保持一次、锚点正文不变与部分交付。
再执行既有 H2/金融回归。离线结果不能证明真实模型成功率，不为这项计数规则消耗付费调用。

Codex 的网络请求/流式重试与模型输出格式补正分属不同层；本变更的“五次”是本项目的用户选择，
不宣称 Codex 所有工具错误统一补正五次。对照本地 Codex 源码，默认 `stream_max_retries` 为 5、
`request_max_retries` 为 4；这解释了“五次”在传输层的来源，但不等于 Codex 对格式错误统一做五次语义补正。
