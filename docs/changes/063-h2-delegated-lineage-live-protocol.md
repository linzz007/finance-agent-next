# H2 R15 Delegated Source Return Diagnostic

Date: 2026-10-20. Status: fixed batch completed and audited; frozen protocol retained.

## Purpose And Authority

The active goal requires baseline implementation, code-level verification and
real Query acceptance. The user authorized necessary paid testing without a new
question for every execution. [062](062-h2-delegated-source-lineage.md) has
offline evidence but no live evidence for the new source return. R15 tests that
boundary once; it is not another all-business rerun or a new reading policy.

Use two explicit diagnostic assignments: L01 single-article child-only reading,
L02 two-author child-only reading and synthesis. Root discovers metadata and
grants its authorized metadata artifacts; children alone read the original
bodies. This distinguishes source return from Root's preexisting source reads.
The diagnostic instructions request this separation; the Runtime does not
enforce a universal child-only financial workflow. These are controlled variants
of S01/S02, not unchanged cases whose scores can be compared directly.

## Frozen Limits

- Reuse the original S01/S02 article/company snapshot and recorded research day.
- DeepSeek profile only, streaming as configured, FakeRedis explicitly labeled.
  No real Redis, Docker, frontend/default-1.0 switch or live-data migration.
- L01 and L02 once each, sequentially. Each whole tree has at most 120 physical
  requests, 60 minutes, the existing 24-call/10-minute Root reserve. Batch ceiling
  240 includes children, one format correction and its permitted transport retry.
- No model switch, budget expansion, extra probes or repetition on failure.
  Stop future cases on quota/provider/environment or integrity/accounting failure.
- Freeze all repository source/design/configuration plus dispatch tests and the
  private wrapper, and copy snapshot before the first request. Check before each
  case and at completion; no source edits while the batch runs.
- Retain every failure, candidate, charge, original answer and raw observation.
  Output is a new private sibling runtime-records/h2-lineage-r15-20261020 folder;
  protocol/audit files have separate sibling directories. Preserve R14 and every
  earlier batch, including their valid pre-edit hash audits.

## Separate Acceptance Layers

1. Accounting/integrity: physical calls, exact model, Task/Attempt/model/budget
   bindings, conserved grants, immutable artifacts and frozen hashes.
2. Scheduling: explicit spawn, durable wait/continue, child result acceptance,
   full-result consumption before Root synthesis; L02 requests both before wait.
3. Source return: enumerate actual successful child article.read events. Compare
   source identity, dates, hashes, line coverage and reader Task against the
   immutable finance_sources section and Root checkpoint/final state. Do not
   count a reference/summary or user export as an Agent full read. Report
   not_triggered when no accepted source-bearing child result returns.
4. Financial content: compare answer assertions with the actual sources,
   distinguish author view from critique, retain time/condition/sample limits
   and do not treat agreement as external verification. Structural correctness
   cannot certify semantic truth or the complete review protocol.

The final report must classify baseline implementation defects separately from
new design choices, missing capabilities and environment gaps. Real Redis,
production integration, the full business catalog and repeated success-rate
measurement remain outside what two diagnostic runs can prove. Pending parser,
correction-input and closing-mode choices stay unchanged.
