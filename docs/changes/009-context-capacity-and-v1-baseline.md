## 2. 本轮边界

1. 研究输入默认额度及总窗口配置上限采用1,000,000 tokens。保留显式较小配置，超过1M的值按1M封顶，Trace同时保留原始配置和实际边界。不把0当无限，0仍表示总窗口未知，实际输入仍由输入额度和1M顶限制约。
2. 实际可用输入为输入额度、总窗口扣除本次输出额度后的空间二者更小，再扣安全余量4096。输出与安全空间继续保留，不能直接发送完整1M输入再索要输出。
3. 主循环在有效参考容量70%时换出，目标为60%；参考容量取输入额度、已配置总窗口（未知时使用项目上限）、1M三者更小。触发不超过实际安全输入上限；若小窗口被输出预留进一步限制，目标按触发的60/70等比降低，保持回差。默认触发700000、目标600000。主循环以研究输出上限计算预留，模型网关仍按每次实际请求的输出额度检查输入。比例为用户选择的初始工程值，不是模型质量最优值。
4. 沿用现有原样落盘、校验、授权恢复及候选交付；不新增模型摘要或隐藏推理保存，不取消证据门控。不强迫模型填满窗口，材料不足时仍立即回答。普通AgentLoop未显式提供新目标值时保持旧换出目标兼容。
5. 同一研究根预算供主、子任务共享；结构化分析、材料读取恢复与模型请求仍执行实际输入检查。任务已知更小窗口时不能以1M绕过限制。Trace记录触发/目标及容量来源为配置，capacity_verified仍false。
6. `.env.local`仅在确有旧显式容量覆盖时修改被授权的容量数值，保留凭证和其他设置；不打印或覆盖密钥。本轮不改变模型默认、输出上限、温度、传输、首正文等待/重试、研究时限和金融策略。

## 6. 冻结批次后修复：工具调用与返回的真实关联

`r009-01`六次已全部返回完整分析。修改本节之前已核对295个代码/设计文件及898个输入文件的哈希，均与冻结清单一致；不再追加付费重跑。两次Q04出现确定性Trace缺陷：调用账本保留失败调用，但金融Runtime只按成功观察的序号匹配账本，第一次失败后标题、调用ID和后续返回错位。实际模型输入和EvidenceRef仍可复核，但这不符合既有T3/T9真实性要求，原始结果不能计作整条链路通过。

修复只恢复已有记录契约，不新增金融策略：

1. `AgentTurn.tool_call_id`仅在实际网关调用时关联其真实`ToolCallRecord.call_id`；成功、失败、超时和权限拒绝均保留可用的真实ID。它是Trace字段，不加入模型收到的工具正文，也不改变公开JSON动作协议。
2. 在网关前被参数校验、规划或预算边界拒绝的动作，没有实际调用记录时保持空ID。不得猜测相邻记录；异常后的Runtime计划恢复调用也不能冒充原动作。
3. 金融Runtime按ID查找账本，而非按成功次数或工具名称猜测。成功返回与失败观察分别记录对应状态、`turn_index`和调用ID；无记录时保留实际动作名称、错误与空调用列表。
4. 主模型Trace同步保留`turn_index/tool_call_id`，使动作、观察、调用账本可直接连接。原始付费Trace不可回写；修复后的确定性回归与冻结真实结果分别记载。

子Agent的角色权限包装器只读转发底层调用账本，不改变授权和本地`artifact_read`行为；本地读取未经过该账本时不虚构ID。通用循环兼容没有调用账本的继承包装器，保持空ID而不使原本可运行的任务失败。

离线验收需覆盖：失败后换工具、同一工具不同参数、网关前契约拒绝、超时、权限拒绝、内部计划恢复、角色包装器、无账本兼容和正常成功。核对ID唯一/不串绑，失败不标成功，实际来源与最终正文不因记录修复改变。通过离线回归不等于已做修复后的真实模型复验。
