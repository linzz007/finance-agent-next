## Presentation Contract

1. Load only already authorized handles. Keep every persisted Artifact, result,
   observation, reader, version, budget entry and original checkpoint intact.
2. Within one model input, identical full material values may share one visible
   payload. Retain every material handle; duplicate descriptors identify the
   canonical visible material via payload_material_ref. Compare exact canonical
   values including wrappers/provenance, not semantic similarity.
3. A successful business receipt whose payload exactly matches a visible typed
   tool-result material retains action identity, status, cache information and
   a payload_material_ref, without another copy of that body. Different values,
   source versions, failures and scheduler data must not be conflated.
4. Explicit normalized_observations/action_observations remain the authoritative
   typed views. The legacy combined observations preserves ordering and status
   metadata; duplicated payload/summary/content/description fields use a
   payload_view descriptor keyed by observation_ref to the explicit view.
   This narrowly refines 086's presentation compatibility, not stored records.
   Small failure diagnostics remain directly visible in their explicit views.
5. A reference to another visible copy is not context offload or evidence of
   reading a new source. Keep expansion handles and do not invent source grants,
   article read progress, result consumption or semantic verification.
6. Actual pressure uses the existing configured context limit. Both Root and
   research child use the same fitting routine after their own prompt is built;
   omit only under pressure, keep all handles and material.get expansion. No
   low fixed length cap, summarization, corpus-wide grants or new threshold.
