# 010：主 Prompt 收口与能力按需加载

日期：2026-10-18。用户要求精简金融主上下文，并明确选择：Skills 正文与详细工具参数均按需读取。此变更只调整能力说明的装配与发现，不改变金融研究目标、分析方法、委派生命周期、预算、来源权限或完整稿交付要求。

## 1. 已确认的设计

- 一份金融主 System Prompt 保存总体目标、先规划/验证/交付原则和公开 JSON 动作协议。JSON 是模型向程序表达“调用哪个工具/提交什么结果”的机器信封，不是另一套金融分析步骤；正文仍自由组织。
- 主 Prompt 附带由配置生成的简短 Skill 目录，每项有稳定 ID 与用途。工具首轮只展示名称、用途；`research.plan`、`skill.open`、`tool.describe` 三个基础工具保留完整参数。主任务不再默认拼入所有 Skill 正文、所有业务参数 Schema 和审核目标 Schema。
- `skill.open(skill_id)` 只读取当前配置声明的可信模块，返回正文、内容校验和，以及该能力下本轮可用工具的名称和用途。来源能力覆盖文章、网页及行情，打开它不应顺便带入所有相关参数；详细参数始终由 `tool.describe(name)` 逐工具查看。必要的能力专用结构（如审核目标）随相应 Skill 返回。参数用 `name`，避免与网关的派发参数 `tool_name` 重名。
- 目录、工具权限、Python 类型校验分别负责发现、授权和执行。读取说明不增加权限，不读取文章，不形成金融 EvidenceRef。允许在创建计划前查能力/参数说明；任何业务取材仍须先规划。不限于金融关键词的自动路由，不强制每题读取全部 Skills。
- 同一运行按首次读取缓存模块内容，重复读取返回同一快照并标记已加载；不重复自动注入 system。后续模型仍能显式回读，不能因缓存使换出后的说明不可恢复。新运行重新建立快照，不跨用户/运行共享可变状态。
- 非目录 ID、路径穿越、未授权工具与缺失/空模块明确失败，记录失败；不能静默改为拼入全部文档。加载错误不允许执行猜测的动作或认证金融结论，已有安全候选稿的保存/交付机制保持不变。

## 2. 模块收口

保留七项：来源访问、研究计划、证据覆盖、验证与审核、角色委派、运行内产物、新版研究交接。`verification.md` 的核心判断并入 `evidence_review.md`；两份 `runtime_execution.md` 不再进入金融主链路，有用的金融来源/口径规则归入来源与审核说明，通用动作协议归入主 Prompt。历史文件仍供既有引用追溯，不批量删除未审查的继承文件。

一般角色介绍与新版交接分开：前者解释角色用途，后者定义可选 analyst v2 的任务与返回；主 Agent 仍可自行分析。审核失败保留完整安全分析、意见一致不等于事实认证、全部/抽样区分等核心边界不因延迟加载消失。

## 3. 接口、Trace 与兼容

正式发现接口记在接口契约第 9 节。新增配置 `capability_catalog`；为空的旧配置保留原有 eager 装配。金融配置启用目录装配，通用/子任务循环默认协议保持兼容，仅金融主循环将动作说明统一取自主 Prompt。

`plugin_load` 区分可用模块与初始已加载模块，记录目录/主 Prompt 的校验和；`skill_load`、`tool_describe` 记录 ID、版本快照、首次/重复读取及长度。完整说明保留在实际工具观测和模型输入 Trace 中，不把业务元数据或密钥塞入目录。

## 4. 验收与范围

检查：首轮不含 Skill 正文/业务参数/审核目标 Schema；基础协议仅一处定义；目录中的用途完整；按需读取能取得精确 Schema；非法 ID/路径/工具拒绝；local-only 和角色权限不放宽；重复读取和跨运行隔离；先规划与正常交付回归。量化比较原装配与新装配的文本规模，不能将字符数当真实 token 数或金融质量提升。

用离线假模型验证“规划 → 读取能力/参数 → 业务工具 → 验证 → 交付”，并运行金融/共享 Runtime 回归。不启动新付费批次；真实模型是否更好选择能力和降低错误率需后续固定协议验证，不能由说明缩短推出。

## 5. 实现与验证记录

已接通配置、按需加载器、主工具网关、实际模型输入、Trace 和正式接口。代码见 `runtime/capability_catalog.py`、`FinanceResearchGateway`、金融 `AgentRuntime` 装配和 `AgentLoopConfig.protocol_in_workspace_prompt`；主要测试是 `test_finance_capability_loading.py` 与金融 Runtime 的实际输入/交付集成测试。

### 5.1 离线结果

- 金融/共享 Runtime 完整回归：**1589 passed / 30 skipped，51 个模块，118.97 秒**；一项继承的 Starlette 弃用警告。临时工作空间、移除真实模型凭证，不累计定向与完整回归的交集。
- 项目分离/配置检查：10/10，0 模型调用。修改代码的 Ruff 关键规则通过。
- 最终主 Prompt 文案收口后，相关定向复核 **41 passed / 1578 deselected，10.66 秒**，与完整回归有交集，不累计。7 份更新文档的 190 个本地链接与锚点检查通过。
- 按需读取集成测试检查真实首轮 system 内容、精确审核 Schema 的后续披露，以及“计划 → 按需说明/参数 → 正文读取 → 验证 → 完整交付”的输入和 Trace；财务语义审核使用固定测试替身，不代表真实金融质量验收。
- 负向测试包括非法 ID/路径、坏目录、加载失败后重试、重复读取不可变快照、跨运行隔离、local-only 过滤、子角色拒绝，以及业务取材不能利用说明查询例外绕过规划。
- 首轮发现 `tool.describe` 的参数与网关 `tool_name` 重名，实际查询未执行；改用 `name` 后保留精确 Schema 和事件集成检查。另一次失败是新增测试误用 `ArticleCorpus` 构造参数，已按既有 API 修正测试夹具，未改变业务实现或断言。

### 5.2 初始说明体积

同一静态工具清单口径下，按 Python 字符长度统计主 Prompt、能力说明、工具描述 JSON 和审核 Schema；新版本增加两项发现工具。此处不含文章、历史、用户问题、角色名单和其他运行状态，不等于整个上下文大小，也不是供应商 token 计量。旧值来自改前只读测量，不据此声称最优上下文或回答质量改善。

| 部分 | 改前字符 | 改后字符 |
| --- | ---: | ---: |
| 主 System Prompt | 6585 | 1743 |
| 初始 Skill 正文 / 用途目录 | 20441 | 442（目录，正文 0） |
| 初始工具说明及参数 | 22209 | 6559 |
| 初始审核目标 Schema | 1622 | 0（按需读取） |
| 合计 | 50857 | 8744 |

这部分初始说明减少约 **82.8% 字符**，不是 82.8% Token 或成本承诺；按需查询也会增加少量模型决策/工具往返。重复说明不自动注入，但模型确实需要时可回读。
