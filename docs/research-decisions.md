# 金融 Agent：研究与技术选型

## 1. 五个研究点是组合，不是五选一

| 研究点 | 研究的问题 | 既有选择 | 当前边界 |
| --- | --- | --- | --- |
| A | 一篇已选中文章怎样保留观点、支撑、条件和主线 | A1：阅读全文后做主张与证据分析 | 浅读/深读由任务决定；连贯文章理解为主要交接，卡片可选；深读全文适配时整体分析，超长才分段并整合 |
| B | 多篇文章怎样围绕问题比较共识、分歧、时间变化与互补 | B3：MoDS 启发的逐文档视角与协调综合 | 主 Agent 可自行或委派比较与综合；使用连贯理解，不强制每篇一个 Subagent，不把不同主题强行比较，不把共识当事实 |
| C | 谁决定读什么、回读什么、查什么、委派与停止 | C1：沿用 ReAct 式动态主循环 | ReWOO/STORM 仍是可选参考，不是默认必经阶段 |
| D | 如何选择重要陈述、核对证据并修订结论 | D*：RARR + FActScore + ALCE 的金融适配 | 按主张类型处理，由主 Agent 选目标；不是 Runtime 机械审每句话 |
| E | 中间状态怎样分层、换出、恢复与保持证据 | E*：MemGPT 式分层上下文与证据恢复 | 原文、完整理解与工作视图可追溯；适配时使用完整理解，真实压力下才换出/缩减；不默认采用向量 RAG |

这些选择来自用户先前确认，不因原文中的空白“最终选型表”或早期“尚未选型”句子而回退。暂定架构选择与“已经用真实金融问题证明优于所有替代方案”是不同状态；后者仍需实验。

2026-10-16 用户确认的全文优先、自由理解与来源外层、跨篇使用连贯理解，是本项目对 A1/B3/E* 衔接的进一步设计，不是原论文新增的结论。见[架构](architecture.md#4-单篇文章与文章集合)及[决策记录](changes/003-article-understanding-review.md#4-已确认的交接形式)。未更换 A-E 研究路线，也未证明这些改动已经提升真实回答质量。

同日进一步确认多篇综合、可恢复工作视图及分析可委派：主 Agent 保持总体目标、衔接和最终交付责任，实际阅读、分析、综合、复核及候选稿可按需派给子任务；读取、任务分析、综合考虑范围分别记录。具体行为与交接见[确认记录第 9 节](changes/003-article-understanding-review.md#9-已确认的多篇综合上下文与分析委派)及[接口契约 4.1](finance_agent_interface_contracts.md#41-target-multi-article-synthesis-and-context-handoff)，不新增“论文已证明本项目更优”的结论。

上述能力的接口集成已选择显式版本化 analyst + 阅读/综合 Skills、共享任务/结果契约及运行内不可变产物，见[正式接口第 8 节](finance_agent_interface_contracts.md#8-versioned-research-integration-contract)。这是工程集成选择，不是新的论文选型。可选新版已实现并完成隔离离线回归，记录见[变更 004 第 7 节](changes/004-versioned-research-implementation.md#7-实现映射与验证记录)；真实金融回答质量及相对替代方案的优势尚未验证。

## 2. 来源与证据边界

| 选择 | 原始来源 | 原工作与本项目适配的区别 |
| --- | --- | --- |
| A1 | [Automated Claim-Evidence Extraction for Political Discourse Analysis，FEVER Workshop 2025](https://aclanthology.org/2025.fever-1.1/) | 原任务是意见性社论的主张与证据提炼；不能称为金融全文观点无遗漏已被证明，也不能把 Workshop 说成 ACL 主会 |
| B3 | [MoDS，NAACL 2025](https://aclanthology.org/2025.naacl-long.20/) | 原方法围绕争议问题组织文档视角；日期演化、金融口径和按需委派是本项目适配 |
| C1 | [ReAct](https://arxiv.org/abs/2210.03629) | 推理与行动交错是控制思路；本项目的权限、证据、交付和故障边界不由论文直接提供 |
| D* | [RARR](https://arxiv.org/abs/2210.08726)、[FActScore](https://arxiv.org/abs/2305.14251)、[ALCE](https://arxiv.org/abs/2305.14627) | 三项分别支持研究修订、事实粒度评估和引用归因；组合后的 Typed-RARR 是项目设计，不是论文已评测完整系统 |
| E* | [MemGPT](https://arxiv.org/abs/2310.08560) | 借鉴外部状态与显式恢复；不表示安装了 MemGPT，也不证明本项目已有生产级持久化调度 |

本轮核验的是飞书迁移一致性，未重新逐篇核对上述论文和实验数值。保留原始链接与原文的限制，不新增论文效果宣称或“业界最优”结论。

## 3. 保留的候选与暂不采用的方向

- A2 文档级主张抽取与去语境化、A3 法律论证角色与摘要重排，是 A 的对照和相关能力，不能替代完整金融短文理解的验收。
- B1 Multi-News 作为聚合基线；B2 FacSum 作为不同论证侧面和少数观点覆盖参考。完整来源和限制见原文候选章节。
- C2 ReWOO 只在任务已知时参考批量执行；C3 STORM 只作复杂研究的可选规划能力，不为普通问题增加固定成本。
- LLMLingua 是上下文压力下的备选压缩；Lost in the Middle 是顺序敏感性诊断依据，不是独立记忆系统。RAPTOR 留作未来长研报/大语料参考；LongT5 等模型层方法不冒充当前 Runtime 能力。
- PaperQA、Chain-of-Note 和原有历史组合的角色已在飞书中降级或作废，全部保留在来源快照，不自动恢复为当前方案。

## 4. 组合约束与后续实验

A 向 B/D/E 提供可回到原文的文章理解；B 输出带作者、日期和主张来源的关系；C 自主调度；D 保留原观点、核查结果与争议；E 保存可恢复证据而不重写语义。任何环节只收到脱离条件的摘要，都可能放大上游错误。

后续对照实验应使用同一文章快照、Query、模型配置和可比较预算，分别测观点遗漏、误归因、条件与时间混淆、证据支持、少数观点保留、答案完整度及顺序稳定性，再看组合是否改善。先前成功的某次调用或单元测试不能替代该比较。

新增选型只有在确实需要改变现有设计时才建立单独决策记录，写清问题、候选来源、机制、取舍、用户决定与验收；不因采用 AI-native 开发就重新选择所有组件。
