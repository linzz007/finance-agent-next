# Verification skill

历史兼容说明：变更 010 后，此模块不再由金融主配置加载；现行验证与审核说明已归并至 `evidence_review.md`。保留本文件供历史引用追溯，不将其作为另一份现行金融规范。

验证是每轮实质分析完成后的必经阶段，但它不是固定的工作流，也不是要求每个句子都联网核查。主 Agent 负责根据问题、分析结果和证据判断验证范围与方法；本 skill 只提供判断框架和可用能力边界。

## 验证阶段要回答的问题

- 本轮最终准备表达的关键结论有哪些？它们分别是文章/机构观点、客观事实、预测、因果解释，还是基于资料的模型推断？
- 哪些结论已经有本轮实际读取的直接证据，哪些只是从文章观点或多个来源的共同表述推出来的？
- 哪些结论需要独立来源、行情数据、时间序列、反例或条件检查？哪些内容只需要保持准确归因，不需要外部验证？
- 当前验证是支持、反驳、只能说明观点一致，还是证据不足？如果无法判断，应保留不确定性并说明下一步可查什么。

## 工具与方法由主 Agent 自主选择

可以按实际问题自由组合：

- 通过 `article.read`、文章 EvidenceRef 和 `article.study` 检查文章是否真的表达了该观点；
- 通过 `web.search` 发现公开资料，再用 `web.open` 读取正文；搜索摘要只能作为线索；
- 通过 `market.snapshot`、`market.series` 和 `market.metrics` 核对价格、区间、日期与统计口径；
- 通过 `research.verify` 保存结构化的 Claim 复核结果；它是对已观察证据的模型复核，不会自动联网，也不是独立浏览的 Subagent；
- 在需要独立阅读、反例、冲突分析或上下文拆分时委派 `analyst`、`skeptic` 或 `verifier`。是否委派、委派范围和返回格式由主 Agent 根据任务决定。

不要求每轮使用以上全部能力，也不要求固定的角色顺序。验证可以很短，也可以针对多篇文章、市场数据和因果解释展开多轮研究；但最终回答必须能区分“已核实”“仅保持作者归因”“推断/假设”和“尚未核实”。

实质分析后使用 `research.checkpoint` 记录关键结论的验证决定、采用的方法、本轮已观察的 EvidenceRef 和证据缺口。它只保存主 Agent 的判断并形成 `verification_decision/result/gap` Trace，不自动核实事实，也不代替独立 Subagent。若后来读取了新证据，最终回答前更新检查点。

## 证据边界

- 作者之间的共识提高的是观点关系的可见度，不自动证明客观事实；
- 相关性、同期变化和搜索结果不自动证明因果；
- 预测只有在时间范围、条件和结果都匹配时才可判断是否兑现；未到期或口径不匹配时保留 `not_due` 或 `insufficient_evidence`；
- `supported` 和 `refuted` 必须绑定本轮实际读取且与主张口径匹配的独立 EvidenceRef；证据不足时不要为了给出确定结论而补造反证；
- Subagent 的输出需要由主 Agent 综合，不能因为“已委派”就当成已验证。

验证不足或出现反证时仍应回答用户的问题。对被反驳的作者观点，保留其准确归因和原文依据，并列呈现反证、适用时间与口径，再说明当前判断；不要把作者观点悄悄删去，也不要把审核意见本身称作独立事实。审核反复未收敛时，Runtime 可以交付清楚标注争议的部分分析，但不得把未审核的原稿直接当作高可信结论。

## Hook 的职责

最终 Hook 只负责检查答案是否能够追溯到本轮已观察证据、引用是否有效、主张分类是否与证据一致、未解决的缺口是否披露，以及是否满足发布安全边界。Hook 不替主 Agent 决定分析方法，不强制联网，不强制使用 `research.verify`，也不把“读过的所有文章”变成答案必须提及的来源。
