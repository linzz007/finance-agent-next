# Evidence Review skill

这是一项描述验证阶段的能力说明。验证阶段本身是每轮实质分析后的必经阶段，但具体取什么证据、验证哪些结论和采用什么工具由主 Agent 自主决定：

先区分作者观点、客观事实、预测、因果解释、模型推断及个人背景。作者观点核对保真归因，不默认联网判对错；预测保留方向、期限和条件，未到期不判已兑现。外部事实的支持/反驳须有实际读取且口径匹配的独立证据，无法判断保持证据不足；仅作者一致不等于独立验证。`research.verify` 是对已观察证据的模型复核，不会自动联网，也不是独立浏览的 Subagent；`research.checkpoint` 只记录验证判断，不自动核实事实。

- 明确区分工具事实、作者/机构观点、基于证据的推断和待验证假设。
- 重要数字、日期、价格、趋势和因果解释应绑定本轮实际读取的证据；本地文章引用实际读取的路径和行号，网页引用实际打开的 URL，行情引用品种、时间窗口和工具返回。
- 多作者观点比较时，把正文行号放在对应的关键判断旁；文末列文章标题或读取范围不能替代逐条结论依据。对已经过去的预测期限，区分“已到期但未验证”和“尚未到期”。
- 验证价格预测时先确认触发条件、截止日期和报价口径；美国交易日与中文文章发布时间需对齐，不能用后一个交易日的反弹否定前一夜下跌。证据不足是“未核实”，不是“证伪”。
- 多篇文章的“已列出”和“已读正文”分别计数；跨月观点变化不能跳过可能改变时间线的相关篇目。独立核验只说明子任务自行取数，不等于多个来源交叉认证。
- 相关性不等于因果性。资料不足时可以给出候选解释和后续核查条件，但不要把候选解释写成已证实原因。
- 来源冲突时保留冲突并解释口径，不用模型记忆裁决。Subagent 的意见是分析材料，仍需主 Agent 综合。

Runtime 可能对最终引用、证据绑定和独立核验执行门控；门控只负责可追溯性和发布安全，不代表本轮必须使用某个固定的分析模板，也不代替主 Agent 完成验证判断。新证据影响结论时，更新验证检查点再交付。

## 终稿审核目标与恢复

主 Agent 在实质研究的最终输出中提供自行选择的 `review_targets`，把真正影响答案的观点或推理链节点交给审核；不需单独审核时可以明确提供空列表。一个 target 代表一个语义审核单元，不是 Runtime 拆出的单句。至少包含 `target_id`、`type`、`scope`、`claim_or_question`、`article_refs`、`evidence_refs`、`review_question`、`external_check_needed` 和 `importance`。`scope=cross_article` 时可用 `relation_type=agreement|disagreement|change_over_time|complementary`，且必须提供文章引用；`relation_type` 不能用于单篇、外部或个人 target。`type=personal_context` 只用于 `scope=personal`。作者观点、跨文章共识或分歧、因果解释、预测和重要模型推断通常值得提交；普通文章元数据不需要语义深审。

漏填列表或顶层类型不合法时，Runtime 保留完整正文，请同一主模型补一次目标元数据；仅返回 `review_targets` 和说明选择范围的 `selection_reason`，不得改写正文或取新证据。允许有理由的空选择，不代表已验证。补充及有界格式恢复失败仍交付安全完整分析，记录审核未完成，不转入旧逐句审核。审核时保留选定证据的完整已观测片段；材料过大仍受输入预算约束，不用关键词裁掉条件来假装完成审核。

Runtime 只校验证据引用、结构和权限，不替主 Agent 决定哪些观点重要。结构化审核失败时，系统先重试原始契约，再调用只负责格式归一化的 `review.normalize` 修复契约；修复不得新增事实或改变研究稿。所有审核失败、证据不足或冲突都必须保留完整研究稿，并在答案中标明审核状态、缺口和争议。审核意见不应替换作者原观点，也不等于独立事实裁决。

## 定向修订与交付选择

审核覆盖表示选中目标是否得到检查，不表示目标一定获证。`limitations` 只是范围说明，非空不要求重写；作者保真、合理推断、预测未到期和证据不足都不能自动写成市场事实已验证。真正缺少参与文章或有效审核结果时仍要披露缺口。

收到目标级反馈后，由你选择补证、只修订受影响的内容、复审或直接带局限交付，没有固定三轮全文重写。普通审核问题尚未解决但已经可以回答时，提交完整 `answer`、`review_disposition="deliver_with_limits"` 和具体 `review_resolution_reason`。不要通过清空目标、换 target_id 或删除作者观点消除争议；保留双方材料、反驳理由及尚未裁定的部分。明确伪造来源、越权和已知确定性错误必须先修复，不能用总免责声明放行。

需要增量复核时，可在 target 中用可选 `answer_context` 数组提供研究稿中逐字存在且可唯一定位的完整语义片段，包含重要条件和限定。Runtime 保留相邻段落与标题语境；引用缺失或有歧义时保守使用全文。不要只摘有利短句。已有完成审核仅在实际目标文本、语境、问题、个人背景与来源版本都不变时复用；相同无进展输入不反复消耗模型请求。没有充分输入时，缓存也不能把未完成审核变成成功。

Runtime 在语义审核前保存完整公开候选及来源检查点。后续模型失败或预算耗尽仍会重新检查并保留已有可用分析，附上真实未决问题；这不是金融结论正确性认证，也不代表进程崩溃后可自动恢复。
